# VOIP-1657 bin-webchat-manager test coverage: plan

Scope: add `_test.go` files only inside bin-webchat-manager. No product code change, no signature or visibility change, no new module. Analysis: `2026-10-26-voip-1657-test-coverage-analysis.md`. Target: hand-written total 80.5% or more (realistic range 81 to 83%).

## Test units (priority order)

1. `pkg/widgethandler`: database error returns of `Get`, `List`, `UpdateBasicInfo` (update fails, re-read fails), `Delete` (first read fails, `DirectV1DirectDelete` fails but deletion continues, delete fails, re-read fails), `DirectHashRegenerate` (first read, regenerate RPC, update and re-read failures); `UpdateBasicInfo` non-positive idle timeout falls back to the default; `Create` (direct creation fails and nothing is stored, store fails and the orphan direct is deleted, orphan cleanup failure is tolerated, re-read fails, non-positive idle timeout falls back to the default); `NewWidgetHandler` returns a non-nil handler holding the given dependencies. Mocks are strict, so a call after a failure fails the test; generated ids come from an injected `MockUtilHandler`.
2. `pkg/sessionhandler`: `Get`, `List`, `Delete`, `End` error returns and the wrapped error identity (`errors.Is`); `Create` store failure (not duplicate), re-read failure, flow trigger failure and `SessionUpdate` failure that still return the session; `NewSessionHandler`.
3. `pkg/messagehandler`: `Get`, `List`, `Delete` error returns; `Create` session read failure, store failure, re-read failure, nil notify handler; `NewMessageHandler`.
4. `pkg/dbhandler` (new file names, no edits to existing test files): two private in-memory SQLite databases (no `cache=shared`, `SetMaxOpenConns(1)`); the shared one of the existing tests is never modified.
   - A closed `*sql.DB`: get and list fail at the query (this includes the refresh read reached from get), `Create`, `Update`, `Delete` fail at the exec before any refresh, for the three entities, returning wrapped errors.
   - A live private database with the schema files of `scripts/database_scripts_test` and an `ABORT` trigger on the table (or a duplicate primary key for create): the exec fails while the database is alive, and the strict `MockCacheHandler` has no expectation, so any cache write after a failed exec fails the test.
   - Update or delete of an absent id: exec succeeds, the refresh read gets `ErrNotFound`, the cache is not written, the caller still returns nil. A cache set error from `MockCacheHandler` after a successful write is ignored by the caller and the call returns nil.
   - Scan failure per entity: widgets, a text value in `session_idle_timeout`; sessions, malformed JSON in `peer` or `local`; messages, an unparsable text in a `datetime` column, to be confirmed at implementation time by a failing scan first. If one entity cannot be made to fail, its scan branches are dropped from the target and the PR says so.
   - Cache hit returns without touching the database; empty `fields` update returns nil without any call; get of an absent id returns `ErrNotFound`; a list filter with an unsupported value type is tried and kept only if `ApplyFields` fails for it; `NewHandler` holds its arguments. `rows.Err()` branches are skipped (not producible with SQLite).
5. `cmd/webchat-control`: `initCommand` returns the root command named `webchat-control` with a `migrate` subcommand and the infrastructure flags registered (flag defaults asserted through `Flags().Lookup(...).DefValue`, which does not depend on the environment). `PersistentPreRunE` is called directly on the returned command with `t.Setenv` of a literal fake DSN, it must return nil and `viper.GetString("database_dsn")` is asserted to equal it (the config singleton is not asserted: its `sync.Once` stays consumed after the first load, so a second iteration would not reload); it opens no connection. `config.Bootstrap` and `LoadGlobalConfig` change the global viper, the logrus formatter and level, and the config state: viper is reset, the logrus formatter and level are restored, and the config state is restored by saving `*config.Get()` and writing it back in cleanup. The `migrate` subcommand is not executed, because it connects to a database (intended exclusion).
6. `cmd/webchat-manager`: `runListen` with a mock sock handler: queue creation failure still returns nil and `ConsumeRPC` is not called; success path calls `ConsumeRPC` once (callback argument matched with `gomock.Any()`), synchronized with a channel signalled in `DoAndReturn` and a 2 second timeout; `initSignal` called once, driven by sending to `chSigs`, with `signal.Stop(chSigs)` and `chDone` drained in cleanup. `main`, `runDaemon`, `run`, `initProm` are left out (external connections, process exit, duplicate route registration).

## Statement budget

Need +74 (1191). Estimates: widgethandler 30, sessionhandler 15, messagehandler 11, dbhandler 40, cmd/webchat-control 8, cmd/webchat-manager 9: about 113 (about 83%). The handler and cmd units are written and measured first; if the total is under 80.5% after the dbhandler units (for example when a scan case cannot be produced), the fallback is `pkg/cachehandler` tests with a test-only Redis stand-in (miniredis, already used by other services at v2.36.1), with the go.mod and go.sum diff reported. `pkg/listenhandler` is not planned: its remaining uncovered statements are response marshal failures and two error mapping lines that no handler can reach.

## Test notes

- Every dbhandler test builds `handler{}` with a mock util handler and a literal `TimeNow` and `TimeGetCurTime` (not the real clock); only the `NewHandler` test uses the real one and asserts non-nil.

- Failing-exec cases for update and delete insert a row first (a trigger only fires on a matching row); absent-id cases install no trigger.
- List scan cases use a valid `tm_create`, a bad value in the target column and a literal token (no real clock); other failure cases also pass a literal token or an injected mock util handler.
- The `runListen` test comment says it records the current behavior (the queue error is logged and nil is returned).
- `initSignal` cleanup receives on `chDone` before `signal.Stop(chSigs)`.
