## 3.2 Verify items added after design review round 1
- dispatchhandler `dispatchDue`: spawned goroutines are awaited through a channel closed in a mock `Do()` with a deadline `select`, never sleep; slot release is proven deterministically by acquiring all `cap(h.sem)` slots from the test inside a deadline select (no `len` read, no polling). Canceled-context case pre-fills `sem` so the select is deterministic, uses two or more due schedules with pre-set lag gauges, and asserts that no dispatch side effect occurs (`Times(0)`) and that the second schedule's gauge keeps its pre-set value (this distinguishes `return` from `continue`). Concurrency cap: with `sem` capacity N and N+k due schedules, an atomic in-flight counter never exceeds N. Lag gauge uses a unique schedule name per case with exact values: 30s late gives 30.0, exactly due gives 0, in the future gives 0 after pre-setting a high value, `TMNextRun == nil` leaves the gauge untouched. `initUninitialized`: an invalid cron is skipped and a later valid schedule still gets `ScheduleInitNextRun` with the exact computed next time; an init error continues to the next schedule; an empty list makes no init call. `reapAbandoned` and `refreshExecutionRows` error paths: pre-set metric value is unchanged; reap count 0 leaves the abandoned counter unchanged. `tick`: a reap error does not stop the later steps.
- subscribehandler `Run`: `QueueCreate`, `TopicCreateWithKind` and `QueueBind` failures each return a wrapped error and `ConsumeMessage` is never called (`Times(0)`); the `QueueBind` error carries the pattern. `processEventRun` with a `customer_deleted` event returns nil while the mock handler call is still blocked on a channel the test releases after checking the return, which proves asynchronous processing; then the call completes within a deadline.
- config: a fresh `cobra.Command` per case (flags would otherwise be redefined); all twelve fields get distinct non-default values so swapped keys are caught; defaults are asserted per field (redis_database 1, tick 10, concurrency 10, retention 90, backup retention 7, endpoint `/metrics`, listen `:2112`, backup dir empty); env wins over the flag default; empty env counts as unset; the second `LoadGlobalConfig` does not pick up changed env (locked); `Get` is checked by loaded values, not by pointer identity. A non-numeric integer env value is not tested. One field is also set through its flag to check that an explicit flag value is honored. All twelve env names are cleared in one helper (set empty, then unset, restored on cleanup) so a polluted environment cannot change default assertions.
- cachehandler: round trip includes the pointer time field both nil and set; after `ScheduleSet` the key is `schedule:<id>` with TTL 24h; Get miss is `redis.Nil` and corrupt JSON is a json error (distinct); Set, Get and Delete after `mr.Close()` return errors; lock key `schedule:lock:<id>` exists with TTL equal to the argument; locks of different schedule ids are independent; `mr.FastForward(ttl)` lets another caller lock; `unlock` after expiry does not panic; `unlock` works with a canceled context; `LockSchedule` with a canceled context returns an error. `Connect` failure uses a closed miniredis address (loopback, connection refused, fast) and the test has a deadline guard.
- backuphandler: `Run` against local `sh -c` (long-running case written as `exec sleep 30` so the kill reaches the process holding the pipes) for known stdout, exit 3 (`*exec.ExitError` plus stderr text), missing binary (`exec.ErrNotFound`, empty stderr) and a canceled context that kills a long command, all under a timeout. `boundedBuffer.Write` always returns `len(p)` even past the limit; boundaries at limit, limit+1 and multi-write; later writes are ignored once full. `truncateStderr` at 4096 (unchanged) and 4097 (cut to 4096). `runDump`: output path in a nonexistent directory (fixed instead of a permission trick, so it also works as root); runner failure error contains stderr and argv; the DSN password check is made through `Backup` with a failing fake runner (error text has no password and the temp defaults file is removed); success output has mode 0600. `Backup` failure leaves no partial file. `prune`: retention 0 and negative keep one file; files with other prefix or suffix and subdirectories are never removed; missing directory returns an error. `writeDefaultsFile` is 42.9% covered today (the earlier statement that it is covered is corrected): the create-temp failure branch is reached with `TMPDIR` set to a nonexistent path. Read-only directory removal failure is excluded because it cannot be reproduced as root.
- Calls against a closed miniredis are slow because of client retries (a few seconds each), so they are grouped into few subtests with a deadline of 15 seconds or more.
- No real `mariadb-dump`, database or broker is called; the only subprocess is the local `sh`.

## 4. Rules
Table-driven, non-parallel for config and for tests touching global Prometheus metrics (unique schedule names per case), existing mock and metric helpers, synthetic values only, no network beyond loopback miniredis, no sleeps for ordering. go.mod diff must contain only added `require` lines for miniredis and its transitive modules (no version bump of existing modules); `go mod tidy` leaves no further diff.

Mutation sampling runs on a `git archive` copy outside the work tree and is restored and confirmed with `git diff` before moving on. Each mutation must fail a named new test; the PR records mutation, failing test name and restore confirmation. Planned mutations: dispatchDue remove the `lag < 0` floor, reverse `now.Sub`, turn the ctx.Done `return` into `continue`; prune start index `retention+1`, remove the lower bound, remove the prefix check; truncateStderr limit constant change (the `<=` to `<` mutation is equivalent and excluded); boundedBuffer.Write return `remain`; cache TTL 24h to 1h, lock key format, remove the busy classification; config swap two keys, change a default, drop the `once`; subscribe Run return nil on QueueBind failure. Moving ConsumeMessage before the bind loop is not sampled because it is scheduling dependent; ordering is held by the existing binding golden test and the `Times(0)` assertions.
