## 4. Rules and isolation
- Table-driven, gomock with strict controllers, synthetic values only (invalid DSN strings, loopback or miniredis addresses, random UUIDs). No sleeps for ordering; goroutine calls are awaited with a channel and a deadline.
- Global state: `config.Get()` returns the process-wide config. A helper first calls `config.LoadGlobalConfig()` to spend the `sync.Once`, then overwrites fields and restores the whole struct in `t.Cleanup`. The helper spends the `sync.Once` first (so `Execute` never reloads config from the environment) and then overwrites the whole config, so a developer shell value never reaches a real server, and cases must not rely on flag values reaching the config. The helper sets the DSN to an explicitly invalid string without a slash (an empty DSN would dial a default local port) and the Redis address to a closed loopback port. Viper is reset after each cobra test; cobra commands are rebuilt per case and use `SetArgs`. Tests that set `TMPDIR` or touch Prometheus metrics are not parallel.
- Not tested because they exit the process or bind global state: `main` of both commands, `cobra.CheckErr` branches, `runDaemon`, `initProm`.

## 5. Verification and mutation sampling
The five-step verification workflow (`go mod tidy`, `go mod vendor`, `go generate ./...`, `go test ./...`, `golangci-lint run -v --timeout 5m`) runs, plus `go test -race -count=3 -shuffle=on` against flakiness on the packages this PR changes (the existing `pkg/dbhandler` tests do not survive `-count` above 1, so that package runs once with `-race -shuffle=on`). Per-package before and after table plus hand-written and raw totals are measured with the command in section 1 and recorded in the PR body. Mutation sampling runs on a full `git archive` copy of the repository outside the work tree (the `replace` directives need the sibling modules): change the default 400 of `processRequest` to another status; change the length check `< 4` to `< 3` in a schedule handler; change the 500 of the failed conversion branch of `errorResponse` to 400; change `printJSON` indentation; remove `cobra.ExactArgs(1)` from `get` (the argument-count tests assert the exact cobra message `accepts 1 arg(s), received 0` and the absence of "failed to initialize handlers", for get, enable and disable); change the UUID-versus-name branch order in `resolveSchedule`; drop the unlock in a manual-execute error path; change the `maxAttempts < 1` guard to `< 0`; drop the continue after a failed customer-delete. After the final tests exist, each mutation is applied once in the scratch copy; an equivalent mutation (no test can fail) is replaced by another. Each mutation must fail a named new test, and the PR records the test names.
