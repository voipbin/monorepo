# bin-schedule-manager unit test coverage to 90% (VOIP-1663)

## 1. Ticket review
Valid. Measured on origin/main 0bfbe2a1d with `GOFLAGS=-mod=mod go test -count=1 -coverprofile=cp.out ./...`: hand-written 87.89% (1786/2032). Hand-written excludes `gens/`, `mock_*.go` and `Code generated ... DO NOT EDIT` files; duplicate blocks keep the max count. The goal is 90%, 90.5% recommended (53 more statements). Most remaining misses are error paths and code that needs a live database or broker.

## 2. Scope
Test files only inside bin-schedule-manager. No production code, signature or visibility change, no new module, no `go.mod` change (tests do not import `pflag`, which `go mod tidy` would otherwise promote). Nothing needs a real database, a remote Redis or RabbitMQ.

## 3. Plan
- cmd/schedule-manager: `runDaemon` with an unparsable DSN, a metrics endpoint from a process-wide atomic counter and a listen address that always fails to bind (a host without a port, such as `127.0.0.1`; an empty value would bind port 80) returns an error carrying "could not connect to the database" (`errors.Is` against the error that `mysql.ParseDSN` returns for the same DSN, a slash-less one so it is the package sentinel; a message substring alone is not enough). `initProm` with that address logs "Prometheus server error" (log hook polled with a deadline) and returns without panic. `main` with `--help` (`os.Args`, stdout and logrus restored): the usage has the root command's short text and the Bootstrap flag names, and the call returns.
- cmd/schedule-control: `main` with `--help` prints the same kind of usage; `initCache` against the address of a cache server that was just stopped returns the wrapped error and a nil cache (one case, bounded by a test deadline, retries are slow).
- pkg/dbhandler: a row holding a wrong-typed value in a private sqlite database (never the shared test one) makes each get and list method return its own scan error marker; the corrupted column is not one the method filters on, otherwise the row is never selected. A stdlib `database/sql/driver` fake reports a `RowsAffected` error and a `Commit` error; each method returns its own marker (a nil result for the one commit path, zero values for the RowsAffected paths) and writes nothing to the cache. Cache helpers: DB miss, cache set error, cache hit. An update map holding a map or slice value that contains a channel is rejected before any SQL, and a read-back shows the row unchanged (a bare channel passes through the converter); a schedule whose target data is invalid JSON is rejected on create.

- pkg/backuphandler: the runner removes the defaults file, or the dump file, while running (`Backup` result and log asserted; the missing dump file is an error). The runner restricts the backup directory mid-run so an old dump cannot be removed, or the directory cannot be listed; `Backup` still succeeds and the log is asserted (permission cases skip when a write into the restricted directory still succeeds, as under root or CAP_DAC_OVERRIDE; permissions are restored in `t.Cleanup`).
- pkg/backuphandler, size limit: the soft file size limit is lowered then restored (the Go runtime ignores SIGXFSZ, so writes fail with a size error; Linux only, not parallel, window kept minimal and logrus output sent to a buffer meanwhile; in a `_linux_test.go` file). The defaults file write fails with a limit of 5 bytes set before `Backup`; the gzip finalize fails with a limit of 5 bytes set inside the runner, after the defaults file exists.
- pkg/schedulehandler: a non-string type, cron and name in an update return the field's own error code, with strict mocks asserting no name check and no DB call.
- pkg/listenhandler: a time value with a year above 9999 makes the response unencodable and gives status 500 with empty data for the execution list and the manual execute handler.

## 4. Rules and isolation
- Table-driven, gomock with strict controllers, synthetic values only. No sleeps for ordering; asynchronous results are awaited with a channel or poll and a deadline.
- Global state is restored in `t.Cleanup`: `os.Args`, `os.Stdout`, the process config struct (after spending its `sync.Once`), viper, logrus formatter, level and hooks, the file size limit, and `signal.Stop(chSigs)`. The `initSignal` goroutine that `runDaemon` starts only ends when it receives from `chSigs`, so the test sends one value on `chSigs`, receives the resulting value on `chDone` within a deadline, and thereby leaves both channels empty for the existing `initSignal` test. Every `initProm` call uses a distinct endpoint because the default mux rejects a repeated pattern. These tests are not parallel.

## 5. Verification and mutation sampling
Expected gain is about 72 statements against 53 needed (cmd about 30, dbhandler about 23, backuphandler about 12, listenhandler 4, schedulehandler 3); the order of work is cmd, dbhandler, backuphandler, then the small ones, and the total is re-measured after each package group. If the total stays below 90.5%, the remaining gap is reported before adding any production change.
The five-step verification workflow runs, plus `go test -race -shuffle=on` on the changed packages, with `-count=2` for the `cmd` packages (`pkg/dbhandler` does not survive `-count` above 1 on main, so it runs once). The per-package before and after table and totals use the command in section 1 and are recorded in the PR body. Mutation sampling runs on a full `git archive` copy outside the work tree, and only mutations that existing tests do not already catch are used: drop the `Commit` error return (asserted as error, nil result and no cache write), drop the connect error wrap in `runDaemon`, swap two scan error markers (one in a get path, one in a list path), drop the old-dump removal error handling and the gzip finalize error handling in `Backup`, invert the type check of one update field, change the 500 of an encode failure. Each mutation must fail a named new test, and the PR records the names.
