# voip-asterisk-proxy: raise hand-written unit test coverage to 90%

## Goal and baseline

Raise hand-written statement coverage (excluding `mock_*.go` and `Code generated ... DO NOT EDIT` files, duplicate blocks merged by max count) from 83.03% (861/1037) to at least 90.5% (939 statements). Only test files are added; no product code, `go.mod` or `go.sum` change (miniredis, gomock and the prometheus client are already dependencies). Most of the gap (107 of 176 uncovered statements) is `main()`, which could not run in a test because `sockhandler.NewSockHandler` opened a real RabbitMQ connection. `sockhandler.SetRabbitFactory` now lets a test hand `main()` a `MockSockHandler`. Expected result: about 92%.

## Planned tests (cmd/asterisk-proxy, new file `main_run_test.go`)

Shared setup for every test (each test runs `main()` in a goroutine behind a 5 second watchdog that fails the test instead of hanging (the result is sent from a `defer`, so a mock violation that ends the goroutine fails at once; if the watchdog fires the abandoned `main()` may still touch restored variables, which is accepted noise on an already failed path), and every `ConsumeRPC` stand-in has the exact eight-argument signature): `prometheus.DefaultRegisterer` is replaced by a fresh registry (the request handler registers metrics with `MustRegister` and would panic on a second `main()` run); the standard logrus logger's `ExitFunc` panics with a sentinel carrying the exit code (`Fatalf` returns to the caller otherwise) and `main()` runs under a `recover` wrapper; the sock factory returns the mock; the package variables the tests set, and `chSigs` (drained before and after), are restored in `t.Cleanup`; `googleApplicationCredentialsJSON` is a malformed JSON so no external credential lookup happens. No test uses `t.Parallel`. Each test uses its own `ariApplication` value and the ARI server reports the `app` query value of every accepted connection, so a connection from another run cannot satisfy the assertion. The AMI endpoint is one package level loopback fake (built directly from `net.Listen` and the existing serve loop, since `newFakeAMI(t)` closes on test cleanup) that is never closed (`main()` never closes its amigo client, which reconnects forever, so closing the fake would leak error logs and reconnects into other tests); the ARI endpoint is likewise a package level loopback websocket server that is never closed (the ARI retry loop cannot be stopped, so closing it would make that loop log reconnect errors for the rest of the binary), reports each accepted connection on a channel and holds it. Redis is miniredis. The interface is the first non-loopback IPv4 interface, chosen like the existing interface test, and the expected id and address are what `getAsteriskIDAddress` returns for it (`t.Skip` when there is none or the hardware address is empty; the 90.5% figure holds on hosts that have such an interface, as CI does). The mock expectations are exact: one `Connect`, one `TopicCreate` with the asterisk event queue name.

1. Success: kubernetes disabled; `chSigs` is pre-filled so the final `select` returns; two `QueueCreate` calls are asserted as (name, type) pairs, `(<permanent>, "normal")` and `(asterisk.<mac>.request, "volatile")`, with `<mac>` read from the same interface; two `ConsumeRPC` stand-ins signal a wait group and wait for cleanup, and the test waits up to 5 seconds for both and for the ARI connection. The redis key `asterisk.<mac>.address-internal` is polled (written from a goroutine) until it holds the interface address.
2. Interface failure: an unknown interface name; `Fatalf` panics with exit code 1 and the mock saw `Connect` only.
3. Kubernetes enabled outside a cluster (`KUBERNETES_SERVICE_HOST` cleared): `main()` returns before any handler is built, so the mock saw `Connect` only.
4. Empty permanent queue name: the listen handler start fails and `Fatalf` panics with exit code 1; the mock saw `Connect` and `TopicCreate` once each and no `QueueCreate` or `ConsumeRPC`.
5. Consumer failure: both `ConsumeRPC` stand-ins signal the wait group and return an error, and the test waits for both, bounded by the same 5 seconds, before finishing; the error reaches the final `select` and `Fatalf` panics with exit code 1 (the `chSigs` channel stays empty).

## Verify

- Assertions check observable values (queue names and types, redis key and value, exit code, mock call counts, ARI accept), never constants compared to themselves. No fixed ports (loopback port 0 only; the existing `init()` metrics listener is unchanged), no external network. Test credentials are fake, and the expected id and address come from the host interface itself; passwords are assigned in separate statements.
- Safe under `-race -count=3 -shuffle=on`.
- Mutation sample in a scratch copy only: swap the permanent and volatile queue names, change the redis key format, drop `setProxyInfoRedis`, drop `evtHandler.Run`, drop the `NewNotifyHandler` call, drop the `return` after an annotation failure, drop the `case <-chErr` branch of the final `select`, and (in `listenhandler`) drop the `QueueCreate` call. Each must fail a test.
- Gates: `go mod tidy && go mod vendor && go generate ./... && go test -race -count=3 ./... && golangci-lint run`, `bash scripts/check-test-conventions.sh` from the repo root, `git diff --stat origin/main...HEAD` limited to `voip-asterisk-proxy/` with `go.mod` and `go.sum` unchanged after the `GOFLAGS=-mod=mod` coverage measurement.
