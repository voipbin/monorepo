## 3. Plan
Test files only, added to the existing `*_test.go` file of each package (new `main_test.go` in cmd/message-manager). Every new test name starts with `Test_` and carries a scenario suffix; gomock controllers are named `mc`; no testify. Fixtures are synthetic: fake phone numbers in the existing masked style, UUID literals, and the DSN is always the obviously invalid value `not-a-dsn` (no slash, rejected by the mysql driver at `sql.Open`, before any connection). A first test asserts that this DSN fails offline with the wrapped initialization error.
Global state rules: `*config.Get()` is copied before and restored in `t.Cleanup`; `viper.Reset()` in cleanup; `config.LoadGlobalConfig` (sync.Once) is never called; `t.Setenv` clears DATABASE_DSN, REDIS_ADDRESS and similar variables; logrus level and formatter changed by `config.Bootstrap` are restored; no `t.Parallel`.
1. cmd/message-control: resolveUUID (empty, malformed, valid); printJSON (success with stdout captured and the JSON checked, unmarshalable value returns the wrapped error); command constructors (names, flags, defaults such as limit 100); runSend validation, one case per branch in order (customer id missing, customer id invalid, source empty, destinations empty, text empty), each with `DatabaseDSN=not-a-dsn` so that a removed validation falls through to the different `failed to initialize handlers` error and the exact message assertion fails, with no connection attempt; initCommand subcommand tree (message: send, get, list, delete; migrate); initHandler, runGet, runList, runDelete with `not-a-dsn` returning `failed to initialize handlers: could not connect to the database`. The resolveUUID branches inside runGet/List/Delete need a database and are excluded.
2. cmd/message-manager: runService with `not-a-dsn` returns the connect error; initProm with endpoint or listen empty returns at once (the enabled path registers an http handler and binds a port, never called); signalHandler: `go signalHandler(); chSigs <- syscall.SIGTERM`, then receive from `chDone` inside a `select` with a `time.After` upper bound (not a sleep); `t.Cleanup` calls `signal.Stop(chSigs)` and drains `chSigs` and `chDone`. runService already starts the same goroutine through initSignal, so assertions are written to hold when an earlier goroutine also consumes the channel (each test only checks that `chDone` gets a value, not which goroutine sent it), each test asserts at its start that `chDone` is empty, and the runService test itself sends SIGTERM and receives from `chDone` so that the goroutine it started is consumed in the same test; the set is run with `-race -shuffle=on -count=3`.
3. dbhandler: the shared sqlite handle (`file::memory:?cache=shared`, one connection) is never closed. Exec and query failures use a per-case handle from a separate `sql.Open` that is closed, or a fake connector in the style of `ctx_rows_test.go`. The scan error case uses a fake driver returning columns equal to `GetDBFields(&message.Message{})` with a wrong value type (the existing one-column `iterErrRows` cannot reach it). Other cases: Get cache hit (db not queried, mock cache returns a message), Get not found (129), cache set error ignored (84, 98), messageUpdateToCache error (94), ApplyFields error with an unsupported filter value (214), plus lines 78 and 199 if reachable.
4. listenhandler: main.go 103 (ConsumeRPC returns an error, run goroutine logs), 137, 214, 216, mapped by reading the code first; no duplicate of existing list/post cases. Others: messagehandler/send.go 96 and messagehandlermessagebird/send.go 33 with mocks, cachehandler setSerialize with an unmarshalable value (a channel). telnyx, messagebird, config and webhook.go are untouched.
