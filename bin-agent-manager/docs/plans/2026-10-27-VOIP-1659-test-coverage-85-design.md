## 1. 티켓 검토 (이슈 분석)

- 도달 가능 상한 산정: 도달 가능한 dbhandler 오류 경로는 미커버 154 중 PrepareFields/ToSql 분기 약 39 를 뺀 약 114 statement 이고(분기 문구 기준 개략 추정이며, `dbErr = err` 지표 블록이 함께 커버되는지는 구현 후 실측), config 약 5 를 더해 필요량을 넘습니다. 필요량(+64~+79)을 넘으므로 block 없이 진행합니다. 실제 증가량은 구현 후 실측으로 확인합니다.
- 최근 커밋/PR: VOIP-1647, 1652, 1657 이 머지되어 있고(#1513, #1583, #1628) 이 서비스에 열린 PR 은 없습니다. 이미 sqlmock 이 go.mod 에 있고 `pkg/dbhandler/ctx_rows_test.go` 가 sqlmock 핸들러 헬퍼를 제공하므로 새 의존성은 없습니다.

## 2. 계획 (verify 항목, 테스트 코드는 아직 없음)

컨벤션: `Test_` 이름, gomock 컨트롤러 이름 `mc`, testify 금지(`reflect.DeepEqual` 과 `t.Errorf`), table-driven, 합성 값만 사용. `uuid.NewV4` 난수 id 를 인자로 쓰는 주소 삽입 쿼리는 `sqlmock.AnyArg()` 로 매칭합니다. 이미 덮인 블록을 지나는 케이스는 행동 단언 추가용(statement 증가 0)으로 간주합니다. 신규 테스트는 sqlmock 과 gomock 만 쓰며 외부 연결, 실시간 시간에 의존하지 않습니다(기존 헬퍼 `newSQLMockHandler` 재사용, 시간은 고정 mock). 이미 기존 테스트가 덮는 항목(빈 주소 목록 삽입, Reserve 0행/1행 정상 경로, Sweep 0건/N건 정상 경로)은 계획에서 뺍니다.

1. pkg/dbhandler/error_paths_test.go (신규, 단일 파일). 각 케이스는 `mock.ExpectationsWereMet()` 로 호출 순서와 Rollback/Commit 여부를 단언하고, 오류 케이스는 `errors.Is` 또는 메시지 포함으로 원인을 단언하고, `AgentList`/`AgentGetByUsername` 의 필터는 맵 순회 순서가 무작위이므로 필터 1개를 쓰거나 느슨한 쿼리 매처(접두 `SELECT`, `FROM`)를 씁니다. 오류 유도: Begin/Commit 은 `ExpectBegin()/ExpectCommit().WillReturnError`, RowsAffected 는 `sqlmock.NewErrorResult`, ErrNoRows 는 빈 `NewRows`, 잘못된 id 는 16바이트가 아닌 `[]byte`, Scan 오류는 열 수 불일치, `row.Close()` 오류는 `Rows.CloseError`.

   - agent_reserve.go: `AgentReserve` Exec 오류와 RowsAffected 오류(0/1행 정상 경로는 기존 테스트 소관이라 제외); `AgentReserveRelease` Exec 오류; `AgentReserveSweep` Query/Scan(열 수 불일치)/parse 오류, 갱신 Exec 오류, N건에서 캐시 refresh 가 건당 agent SELECT(id 별 `WithArgs`) → addresses SELECT → `cache.AgentSet` 순서로 정확히 1회씩 일어나고 반환값이 N 임(기존 테스트에 없는 `AgentSet` 호출 수 단언이 이 항목의 가치).
