## 3. Verify

- Every new test is deterministic: no real network except closed `127.0.0.1` ports and in-process fakes; DSNs use a fake account name and no password. Test values are synthetic. Before push the added lines are grepped for e-mail addresses, phone numbers, private IP ranges, host names and tokens. The year 10000 time is a fixed `time.Date(10000, 1, 1, 0, 0, 0, 0, time.UTC)`.
- Goroutine based statements (consume error logs in `listenhandler/main.go:156`, `:177` and `subscribehandler/main.go:139`) run after the mock returns, so, for the error cases that log, tests wait on a logrus hook that matches the log message. The two goroutines of `listenhandler` log the same message, so the hook counts matches and the test waits for 2 (a hook with a capacity-1 non-blocking send, like `hookFunc` in package main, would drop the second one), or each queue returns a different error text that the hook tells apart. Success paths log nothing: there the `DoAndReturn` of each `ConsumeRPC` or `ConsumeMessage` closes one channel per expected call and the test waits for all of them before it ends (otherwise a mock call after test completion panics or fails under `-race`). The hook helper is defined in the test file of each package (the cmd helper `hookFunc` is package main only). Waiting is a `select` with a 5 second timeout (as in `Test_Run` of `pkg/listenhandler/main_queue_test.go`), `DoAndReturn` signatures use the exact parameter types so a mismatch cannot hang inside a goroutine, and `-timeout 120s` is set in the commands below. Mock calls made by those goroutines (`ConsumeRPC` twice for `runListen`, including the case where the volatile queue creation fails after the first goroutine started) are all expected and awaited before the test ends.
- Global state restored in cleanup: `*config.Get()` (`saveConfig`), viper, logrus hooks and output (`ReplaceHooks`, `SetOutput`), `signal.Stop(chSigs)` with a drain of `chDone`, and `PrometheusEndpoint` stays empty so no duplicate `http.Handle` happens. The `runDaemon` test does not use `t.Parallel` and ends the `initSignal` goroutine in cleanup by sending `os.Interrupt` to `chSigs` and then waiting for `chDone` in a `select` with a 5 second timeout (never a non-blocking drain, which could leave a late value for the next test), then calls `signal.Stop`, and follows the cleanup of the existing `Test_initSignal` (send `os.Interrupt` to `chSigs`, drain `chDone`, `signal.Stop`) and asserts the returned error text; it does not count goroutines because the shared database helper leaves its opener goroutine behind when the ping fails. dbhandler tests that insert malformed rows use a private in-memory database with `SetMaxOpenConns(1)`, the schema from `scripts/database_scripts_test/*.sql`, and a filled `tm_create` so the row is not filtered out. The reschedule RPC of HealthCheck runs in a goroutine, so tests wait on a channel closed in `DoAndReturn` (5 second `select`), not on `time.Sleep`. Existing helpers (`saveConfig`, `closedAddr`, `hookFunc`, `promEndpointSeq`) are reused, never redeclared.
- Assertions check specific returned errors, error text and mock call arguments; no empty calls and no self-comparison.
- Mutation sample, at least one per area, 5 or more in total: cmd (`runListen` error wrapping), dbhandler (empty token default), listenhandler (marshal failure to 500), transcribehandler (non-not-found lookup error), plus dbhandler update value conversion (nested `chan`). Each is done in a scratch copy and the test must fail.
- Commands: `GOFLAGS=-mod=mod go test -count=1 -race -timeout 120s ./...`; `go test -count=3 -shuffle=on -timeout 120s ./...` for the new packages; hand-written total measured with the same profile merge as section 1 (blocks of generated files excluded, duplicates by max count) must be 85.5% or more; the five root CLAUDE.md steps in order, with the `GOFLAGS=-mod=mod` measurement run after `go mod tidy` and a final `git status --porcelain --ignored` that shows no profile files left in the service directory (profiles are written to the scratch directory only) (`go mod tidy`, `go mod vendor`, `go generate ./...`, `go test ./...`, `golangci-lint run -v --timeout 5m`); `bash scripts/check-test-conventions.sh` (run from the repository root, where the gate scripts live) (added lines only: `Test_` prefix, no testify, gomock controller named `mc`; needs `git fetch origin main`) and `bash scripts/check-structure-conventions.sh` after `git add` of the new files; the final `git diff --stat origin/main...HEAD` shows only new `_test.go` files and this document, with no `go.mod` or `go.sum` change.
- VOIP-1416 (packages below 80%) overlaps only on the two cmd packages (61.1% and 12.2%); this is stated in the PR body and not absorbed.

## 4. Test plan (design)

Only new `_test.go` files are added (existing test files are not edited), named after the code under test.

- `cmd/transcribe-manager/main_run_test.go`: `runListen`, `runSubscribe`, `runStreaming` with `sockhandler.MockSockHandler`, `transcribehandler.MockTranscribeHandler`, `transcripthandler.MockTranscriptHandler`, `requesthandler.MockRequestHandler`, `streaminghandler.MockStreamingHandler`. `runListen`: queue create error; volatile queue create error (first `ConsumeRPC` still expected and awaited); success (two `ConsumeRPC`). `runSubscribe`: queue create, topic create, queue bind errors; success with `ConsumeMessage` awaited (`QueueBind` expectations use `AnyTimes` with argument matchers, because the pattern list is internal to subscribehandler). `runStreaming`: `Run` error wrapped; success. `runDaemon`: closed loopback DSN returns the wrapped connect error.
- `pkg/transcribehandler/start_lookup_errors_test.go`: Start with a caller-specified id: `TranscribeGet` returns a plain error (asserted with `errors.Is`, since `Get` wraps it) for `start.go:90`; recording reference valid (`CallV1RecordingGet` ok), `GetByReferenceIDAndLanguage` not found, `TranscribeCreate` plain error for `:97` and `:99`; live reference valid, streaming start succeeds, `TranscribeCreate` plain error, rollback `streaming.Stop` expected, for `:124`. The reference lookup itself succeeds in every case, because an invalid reference returns earlier.
- `pkg/transcribehandler/health_confbridge_test.go`: `CallV1ConfbridgeGet` returns an error with a transcribe that has retry count below the limit; asserts `Stop` is attempted (db get, then the stop chain of the mock reqHandler as in `Test_HealthCheck_referenceGetError_stopFails_reschedules`) and, when stop fails with the retryable error, one health-check reschedule RPC.
- `pkg/transcribehandler/event_delete_error_test.go`: `EventCUCustomerDeleted` where `Delete` of the first transcribe fails (get error) and the second is deleted; asserts both ids reached the db mock. `pkg/transcribehandler/transcribe_delete_stop_ok_test.go`: Delete of a progressing transcribe where `Stop` succeeds (built from `Test_Delete_stopFailsButDeleteProceeds` with a successful streaming stop and status update), then the delete proceeds. `main_bcp47_test.go`: `getBCP47LanguageCode("zz-invalid")` is `en-US`.
- `pkg/listenhandler/response_marshal_error_test.go`: `errorResponse` with a `VoipbinError` whose `Details` holds a `chan` returns 500; Start, List, Get, Delete, Stop and transcripts List with a mocked result whose `TMCreate` is in year 10000 return 500. `pkg/listenhandler/consume_error_test.go`: both queue goroutines log the consume error (log hook awaited), no panic.
- `pkg/dbhandler/*_test.go`: `transcribe_branches_test.go` and `transcript_branches_test.go`: list with empty token uses the mocked current time, update with empty fields is a no-op, update-to-cache read error, unsupported filter type (a struct value) for the two list functions (get-by-reference uses fixed filter types and is not a target), update value conversion error (the conversion judges the Go type of the value, not the field, so a `[]chan int` value for a field key such as the streaming ids of a transcribe or any other field key of `models/transcript/field.go` makes the JSON marshal fail; a top level `chan` only fails at exec and is already covered), transcript cache hit, and malformed stored rows (a `BLOB` of 3 bytes in a uuid column) on a private in-memory database for the scan error paths; `row.Err()` branches are not targets.
- `cmd/transcribe-control/main_migrate_test.go`: the `migrate status` subcommand with a malformed DSN returns an error without network (the DSN is set in both viper and `config.Get()`, with `resetViper` and `saveConfig` cleanup).
- Single statements: `models/transcribe` unknown status (transition check returns false), `models/*/webhook` `CreateWebhookEvent` with a year 10000 `TMCreate`, `cachehandler` `setSerialize` with a `chan`, `gcpRun` with a nil client returns the not initialized error, `streamingHandler.Delete` of an unknown id keeps the map unchanged, `subscribehandler` consume error log (log hook).

Wherever several inputs exercise the same function they are rows of one table test (`docs/conventions/testing.md` 13.1); a single test function is used only when the setup differs.

The BCP47 fallback test is a new file because existing test files are not edited; the PR body says so.
