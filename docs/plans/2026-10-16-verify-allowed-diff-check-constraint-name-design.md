# verify-service-migrations.sh: allow CHECK constraint name differences (VOIP-1601 P0d)

Valid. After PR #1431 (merged, 530421ac5) `E1_ALLOWED_DIFF` accepts TBL/COL collation pairs and the `fk-name` and `column-order` directives. Not covered: the existing `contact_cases` has the CHECK names `chk_cases_peer_type_nn` and `chk_cases_peer_target_nn`, the Alembic head has `chk_contact_cases_peer_type_not_null` and `chk_contact_cases_peer_target_not_null`. A baseline that keeps the existing names differs from E1 in the `CON` (type `CHECK`) and `CHK` lines, name field only. The strict path and the `REFERENCE_DUMP` comparison (the existing database as reference) stay as they are; the baseline is decided by the existing table, so only the Alembic head comparison needs the allowance  (the result must be identical to the existing table; the reference comparison proves that, so the docs make the `REFERENCE_DUMP` comparison (dump of the existing database, its `ALLOWED_DIFF`) required PR evidence for a service that uses `check-name` (it runs on the one engine of `REFERENCE_ENGINE`, the other engine is skipped); the script enforces its presence, see section 2).

## 2. Change (verify script and docs only; no Go code, schema or `.circleci` change)

New directive in the same `E1_ALLOWED_DIFF` file: `check-name <table>` (same grammar as `fk-name`: one space, a table of `$TABLES`, no duplicate, no CR).

- `check_allowed_file`: all four places that name the directives accept `check-name` (the `bad` filter, the `grep -qE` for at least one entry, the duplicate check, the table loop), plus the messages, the script header usage and the `E1_ALLOWED_DIFF` variable line.
- `canon_dump` gets a fourth argument (check-name tables). Per listed table section, each CHECK is identified by its expression (the `CHK` line, all fields after the name). The names are sorted by (expression, name) and renamed `chk#1`, `chk#2`, ... in the `CON` lines whose type is `CHECK` and in the `CHK` lines. Renamed `CON` lines go after the unchanged `CON` lines (as for `fk-name`, sorted by new index), `CHK` lines are sorted by new index. A table with fk-name and check-name together renames both in one `CON` group (check keys sort before foreign key keys). Without the directive the output is byte identical (existing identity test).
- Pairing: only names that have both a `CON` (type `CHECK`) line and a `CHK` line are renamed; an orphan `CON` or `CHK` line keeps its name and so stays a diff. The check signatures and rename maps are separate from the foreign key ones (`nnc`/`nidxc`; the `CON` branch handles `dofk || dochk`; the check block in `section()` is independent of the fk block). Keys: only inside the `CON` group, where checks and foreign keys are mixed, the keys are `c%06d` (check) and `f%06d` (foreign key); the `KCU`/`FK` blocks keep `%06d` with `999999` for orphans, and the new `CHK` block uses `%06d` with `999999` for orphans, so the existing fk-name behavior is unchanged. In the `CON` group the unchanged lines are printed first and the renamed ones follow (as for `fk-name`). Sort keys are strings (awk concatenation with `""`, so an expression like `1` is not compared as a number) with a kind prefix (`c` for checks, `f` for foreign keys, so `chk#1` and `fk#1` never share a key and the order does not depend on the input order).
- Accepted: only a pure rename. Kind (`CHECK` in `CON`), the multiset of expressions and the number of checks must be equal; a changed expression, an added or dropped check, a check changed to another kind or an unpaired line stays a diff and fails. Two checks with the same expression are interchangeable.
- Guard against a swap: a name that exists in both E1 and E2 must have the same expression in the same table, otherwise the same name would point to another check and a later `DROP CHECK <name>` would act on another one. `check_name_guard <e1 dump> <e2 dump> <tables>` projects the raw dumps of all check-name tables together (one record per `CHK` line: name, table, expression) and fails (message, rc 1) when a name present on both sides has another set of (table, expression) pairs in E2 (compared per name; on MariaDB the same name may exist in several tables). It is global over the listed tables because MySQL check names are unique per schema (ER 3822), so a swap between two tables would otherwise pass. `compare_e1` runs it first and ORs its rc into the returned rc (today `compare_e1` returns only the last `compare_dumps` rc); the canonical comparison still runs and prints. Only names present on one side are paired by expression (the rename). The asymmetry with `fk-name` (a swap of two foreign key names passes) is deliberate and documented: a check is dropped by name (`DROP CHECK <name>`), a foreign key name carries no such use here.
- Signature separators: the sort key joins expression and name with the awk literals `"\003"` (as the fk code does), a single `\001` between fields of a signature, so `("ab","c")` and `("a","bc")` never share a key.
- Fail closed for the reference: `E1_ALLOWED_DIFF` that holds a `check-name` directive requires `REFERENCE_DUMP` (and so `REFERENCE_ENGINE`), and its `ALLOWED_DIFF`, if any, must not hold a line matching `^[<>] (CON|CHK)(\t|$)` (an added restriction, so the reference comparison cannot be relaxed on the check lines). Both checks sit next to the existing `ALLOWED_DIFF` without `REFERENCE_DUMP` check (before any container starts). The requirement is that the baseline result equals the existing table, and only the reference comparison shows that. The comparison itself is unchanged; it runs on the `REFERENCE_ENGINE` engine only, so equality to the existing table is shown for that engine, and the script cannot see whether the reference dump is genuine (stated as a limit). The docs require, in the service PR: all checks of a `check-name` table are explicitly named (unnamed checks get engine specific names, which the reference dump cannot cover for the other engine) and ENFORCED; this is enforced by the docs and the PR review only, not by the script.
- Implementation notes: in `canon_dump` the `CON` branch tests `dofk &&` and `dochk &&` separately, and both map sets (`nn`/`nidx`, `nnc`/`nidxc`) are deleted at every section start, so a stale map of an earlier table cannot rename lines of a later one; a fk-only table behaves as today (existing tests). A renamed check is `chk#N`; if a kept orphan line already carries that exact name the canonical dumps differ and the comparison fails (a real dump never has an orphan line; two engines give each `CHECK` both a `CON` and a `CHK` line). Two checks with the same expression are interchangeable by design (accepted limit: a later by-name `DROP CHECK` cannot tell them apart in the head; E1 runs the later migrations on the head names and would show it). A check name of a table outside the list that collides is refused by the engine in E2 (MySQL ER 3822). The guard output lines start with `CHECK-NAME-GUARD:` so they are not counted as `ALLOWED-DIFF` or `UNUSED-ALLOWED-DIFF`.
- `report_directives` gets the check-name tables: `ALLOWED-DIFF check-name <table>` when the raw `CON` (CHECK) and `CHK` lines of the table differ between E1 and E2 (a name or an expression difference; an expression difference fails the comparison anyway), otherwise `UNUSED-ALLOWED-DIFF check-name <table>`. `compare_e1` passes the new table list. The success line keeps its form (counts of `ALLOWED-DIFF` and `UNUSED-ALLOWED-DIFF` lines).
- Unchanged: strict diff without the variable, the `REFERENCE_DUMP`/`ALLOWED_DIFF` comparison (no relaxation; only the new precondition above), pair lines, other directives, V2.
- Limits to document: unnamed checks get engine names (`<table>_chk_N` on MySQL, `CONSTRAINT_N` on MariaDB), a difference of those names is absorbed too, which is the intent; the dump has no `ENFORCED` field (existing limit, a NOT ENFORCED check on one side only is not seen by any comparison; the docs ask the service PR to state that all checks of the table are ENFORCED); a later migration that drops a check by the baseline name fails in E1 when the head has another name, so it shows (the guard covers only a name present on both sides with another expression); MariaDB names column level checks (also the implicit `json_valid` of a JSON column) after the column, so they practically follow the column name and their expression stays compared; the name scope differs (unique per schema on MySQL, per table on MariaDB), the guard is per table; an index or other object is not covered.
- Docs: script header, `docs/workflows/service-owned-migrations.md` (Checks list lines on the E1 directives with an example, the sentence that lists accepted differences, and a rule next to baseline rule 5 for CHECK names); the swap asymmetry with `fk-name` is explained there.

## 5. Verification

- `--self-test` (no docker part): `mkd` is extended with `CHECK` `CON` lines and `CHK` lines (a new argument for the checks); the swap test must pass the canonical comparison alone and fail only by the guard (both shown); file check (`check-name` accepted, also together with `column-order` and `fk-name` of the same table; unknown table, duplicate, typo, extra word, CR fail); `canon_dump` identity; compare_e1 positives (renamed checks, with `fk-name` for the same table as well, two checks with the same expression, equal names reported unused; `check-name x` and `fk-name x` together are not a duplicate) and positives also an expression that is only a digit (string compare); negatives (a swap of names between two check-name tables, `check-name` without `REFERENCE_DUMP` refused, a partial swap with a shared name, a swap of two names with different expressions, an orphan `CON` or `CHK` line, changed expression, added or dropped check, a rename plus an expression change, a CHECK renamed to a non check kind, directive for another table, `fk-name` or `column-order` alone not accepting a check rename, `check-name` alone not accepting an fk rename).
