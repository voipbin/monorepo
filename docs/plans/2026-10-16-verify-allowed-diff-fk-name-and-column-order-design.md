# verify-service-migrations.sh: allow foreign key name and column order differences (VOIP-1601 P0c amend)

## 1. Ticket review

Valid. After PR #1430 (merged, afdf60fd5), `E1_ALLOWED_DIFF` accepts only TBL/COL collation pairs (`check_allowed_file`). A baseline that reproduces an existing table still fails E1 (Alembic head plus service migrations) versus E2 (empty database plus service migrations) in two more cases, both measured by the infra evidence: (B) MariaDB gives an unnamed foreign key the name `1`, `2` (MySQL: `<table>_ibfk_N`), while the existing table has `<table>_ibfk_N`; only the name field of the `CON`, `KCU`, `FK` lines differs. (C) A generated column sits at another ordinal; the column set and every definition are equal, only the `COL` ordinal and the position of the `COL`, `DEF`, `GEN` lines differ. Both are engine independent in principle.

## 2. Change (verify script, docs; `migrationcheck` unchanged: a named foreign key is already accepted)

The dump lines carry no table name, so a diff line list cannot express (B)/(C) (a reorder moves every line of the table). The two kinds are declared per table with directive lines in the same `E1_ALLOWED_DIFF` file, next to the existing `<`/`>` collation pairs:

    fk-name <table>
    column-order <table>

- `check_allowed_file`: behavior change (stated): a non empty line must be a `#` comment, a `<`/`>` pair line (as today), or exactly one directive (no leading or trailing blank, one space) with a table of `$TABLES`; anything else (free text that used to be a comment, typo, unknown table, duplicate directive, CR) is refused before a container starts. Blank lines stay allowed. The file needs at least one pair line or directive (today: one pair line). No service uses the file yet (checked on origin/main and the remote service migration branches).
- New `canon_dump <dump> <fk tables> <order tables>` (awk run with `LC_ALL=C`, per `## table` section; with no listed table the output is byte identical to the input, covered by a test; the canonical dumps go to separate files, `e1-after.txt` and `e2.txt` stay the raw dumps used by the other checks; other tables and lines unchanged; sorting is a small insertion sort inside awk, no `asort`, so mawk and gawk behave the same):
  - `column-order`: the `COL` lines are sorted by column name with the ordinal blanked; the `DEF` and `GEN` lines are sorted by column name. Column set, type, nullability, extra, charset, collation, comment, default and expression stay compared, so an added, removed or changed column still differs.
  - `fk-name`: every foreign key name in the `CON` (type `FOREIGN KEY`), `KCU`, `FK` lines is replaced by one signature per foreign key name that joins all its `KCU` lines (ordinal, column, referenced table, referenced column, in ordinal order) and its `FK` line (update rule, delete rule, referenced table) with a separator that cannot occur in a name; the signatures are sorted (`LC_ALL=C`) and the keys are renamed `fk#1`, `fk#2`, ... in that order, the new name replacing the old one in the `CON` (only lines whose type field, `$3`, is `FOREIGN KEY`), `KCU` and `FK` lines (column and rule stay coupled per key, so a swap of rules between two keys stays a difference; the separator inside the signature is the awk literal `"\001"`, which cannot occur in a dump line except in a hostile quoted identifier). The rewritten `CON` foreign key lines are taken out of their group and placed after the unchanged non foreign key `CON` lines (which keep their order), sorted by new name; the `KCU` and `FK` groups are sorted by new name, then original order. Two keys with the same content get two names and compare as equal pairs. Kind, columns, referenced table and columns and the ON DELETE/UPDATE rules stay compared, so only a rename passes (a swap of the names of two keys is a rename too and passes) (two foreign keys with the same content are compared as a multiset).
- Main comparison (E1 vs E2): with `E1_ALLOWED_DIFF` set both dumps go through `canon_dump`, then the existing `compare_dumps` with the pair lines runs. The canonical `COL` lines of a `column-order` table have an empty ordinal field, so a collation pair line for such a table is written with an empty second field (documented; the printed diff line shows it; a wrong line fails, never silently passes). Pair lines apply to all tables as today.
- Report, independent of pass or fail, per directive and table on the raw (not canonical) dumps: `fk-name` is used when the `CON` (foreign key), `KCU` and `FK` lines of the table differ between E1 and E2 (so a swap of names between two keys counts as used; a rule difference also counts as used, and then the main comparison fails anyway), `column-order` is used when the `ordinal:name` list of the `COL` lines differs (the collation field is not part of it). Used: `ALLOWED-DIFF <directive> <table>`; otherwise `UNUSED-ALLOWED-DIFF <directive> <table>` (an engine without the difference, for example MySQL for `fk-name`; a directive unused on both engines is stale and the PR removes it). The success line keeps the form of today (`N accepted lines used, M unused`), counting the printed `ALLOWED-DIFF` and `UNUSED-ALLOWED-DIFF` lines (pair lines and directives).
- Unchanged: strict `diff` when `E1_ALLOWED_DIFF` is unset, the `REFERENCE_DUMP`/`ALLOWED_DIFF` comparison (diff 0 against the existing database, no relaxation), V2 strictness.
- Limits to document: an index named after a foreign key differs in `IDX` and fails (safe; the talk evidence has no `IDX` difference, its indexes are explicitly named); a later migration that drops or names a foreign key (`DROP FOREIGN KEY <name>`) can behave differently per engine, and a swap of two key names is accepted as well; `column-order` assumes no code depends on column positions (`INSERT` without a column list, positional `SELECT *`), which the service PR states.
- Docs also state: a service whose E2 is MariaDB and whose baseline uses the existing `_ibfk_N` names still needs `ALLOWED_DIFF` for the `REFERENCE_DUMP` comparison (unchanged); an example pair line of a `column-order` table with the empty ordinal field.
- Docs: header of the script, `docs/workflows/service-owned-migrations.md` (the Checks list and the "accepted only when identical" sentence: the two directives and what each accepts).

## 3. Out of scope

Service baselines, `.circleci`, `migrationcheck`, CHECK constraint names, index names, relaxing the reference comparison.

## 4. Impact analysis (no schema or runtime change)

Developer script and docs only; no DDL in production code, no service behavior changes. The script default (unset variable) is byte for byte the strict path.

## 5. Verification

- `--self-test` (no docker part): directive file checks (unknown table, typo, duplicate, only comments, CR), `canon_dump` positives (renamed foreign keys, reordered columns, both) and negatives (changed referenced table, column, ON DELETE rule, a changed column type, an added or dropped column, a changed default or generated expression, a table not listed). A swap of the names of two keys is accepted and reported as used. The reorder with a changed definition, the rename with a changed rule, and a swap of rules between two keys with the same referenced table must stay different.
- Real dumps (offline, not committed): the infra evidence talk dumps (E1a vs existing) give diff 0 with the two `fk-name` directives plus the existing collation pairs and fail without; the contact dumps (existing database versus Alembic head; the verify compares Alembic head plus service migrations with the baseline result, so the CHECK lines concern the reference comparison) give diff 0 apart from the four CHECK name lines (`CON`, `CHK` of `chk_cases_peer_*`, a known difference between the Alembic head and the existing database that this change does not accept; a baseline that keeps the head names has none, the reference comparison lists them in `ALLOWED_DIFF`) with the `column-order` directives for the three contact tables, and fail without.
- Scratch end to end on both engines (`mariadb:12.3`, `mysql:8.0`): a copy of `bin-tag-manager` whose baseline recreates Alembic tables with `_ibfk_N` names and a reordered column order; PASS with the directives (`ALLOWED-DIFF` or `UNUSED-ALLOWED-DIFF`), FAIL without. `bin-tag-manager` verify and `--self-test` on both engines; if the host load breaks a run, rerun per engine.
