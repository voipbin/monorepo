# VOIP-1573 Flow AI Builder: Implementation Plan (retroactive)

Written after implementation from the design (`2026-10-07-flow-ai-builder-design.md`). Reviewers must check that the plan is complete, ordered, testable and consistent with the design and with the actual code; the diff is `git diff origin/main...HEAD` in this worktree.

## Phases

1. bin-common-handler `models/address` (`IsExternalEndpoint`, with `external_test.go`), then bin-flow-manager `models/action`: `meta.go` (Meta{Exposure, Flow} with the FlowKind type), `ref.go` (ref tags action/resource/address), ref tags on every UUID-typed, map-of-UUID and address option field (30 tags in `option.go`), drift-lock tests (`Test_MetaCoversAllTypes`, `Test_EveryUUIDFieldIsTagged`, `Test_BuilderExcludedTypesAreInTypeListAll`; strings and other non-reference fields are not checked), golden test for exposure. The design section 8 names (`TestMetaCoversAllTypes` etc.) differ from these `Test_` names.
2. bin-ai-manager, built and tested together because the pure-logic tests call handler-side symbols (`FlowCatalog`, `FlowSystemPrompt`, `FlowAllowedTypes`, `FlowParse`, `ReconstructGraph`) and do not compile on their own: `pkg/actioncatalog` (descriptions and `Required` flags corrected; `RequiredFields` reads the `Required` flag of each catalog entry; the catalog does not reference `Meta`), `listenhandler/models/request/builder.go`, `models/flowbuilder` (request/response types, limits and request validation in `validate.go`, tested by `Test_ValidateRequest*`), builderhandler `flow_transcode`, `flow_option`, `flow_layout`, `flow_validate`, `flow_schema`, `flow_prompt` (reads `Meta`/`IsBuilderExposable`), `flow_turn`, `flow_main`, `flow_chat`, `flow_parse`, `flow_reconstruct`, `mock_flow_main.go`; cachehandler Flow daily counter and its mock; listenhandler `/v1/flow_builder/chat` (a `flowBuilderHandler` field injected in `listenhandler/main.go`; `runListen` in `cmd/ai-manager/main.go` takes it as a parameter); metrics prefixed `flow_builder_` (`flow_builder_chat_total`, `flow_builder_chat_duration_seconds`, `flow_builder_tokens_total`, exposed with the `ai_manager_` namespace) plus a separate panic counter (`RecordFlowPanic`).
3. Plumbing: bin-common-handler RPC client (`address.IsExternalEndpoint` belongs to phase 1, see ordering); bin-openapi-manager `POST /flow_builder/chat` and the regenerated code (`bin-openapi-manager/gens/models/gen.go`, `bin-api-manager/gens/openapi_server/gen.go`, `openapi_redoc/{api.html,openapi.json}`) plus regenerated mocks (`servicehandler/mock_main.go`, `requesthandler/mock_main.go`); api-manager also adds the `api_manager_flow_builder_timeout_total` and `api_manager_flow_builder_circuit_open_total` metrics; bin-api-manager `server/flow_builder.go` (the HTTP handler: logged-in agent check and the 512KiB body limit `flowBuilderMaxBodyBytes`) with `server/flow_builder_test.go`, and `servicehandler/flow_builder.go` with shared `mapBuilderRPCError`; docs (`bin-ai-manager/docs/operations.md` belongs with phase 2; `bin-api-manager/docs/operations.md` and `routing.md` with this phase), and the three plan documents under `docs/plans/` (design, issue analysis, this plan).
4. Front (monorepo-javascript): `createBuilderStore` factory (Assistant behavior and tests unchanged), `views/flows/builder/*`, entry card and apply path in `flows_create.js`, logout cache clearing.
5. Verification (runs after each phase and at the end): unit tests per phase, mutation checks of defenses, lint (golangci-lint, eslint), convention gates, front jest and build, real-browser check with mock API, scenario replay of eight realistic flows.

## Ordering and dependencies

Phase 1 before 2 (the prompt, transcoder, layout, reconstruct and chat steps read `Meta`; the validator does not). `bin-common-handler/models/address` (`IsExternalEndpoint`) is built with phase 1, because `flow_option.go` in phase 2 calls it and would not compile without it. 3 depends on 2 for the RPC shape. 4 depends on the OpenAPI wire form from 3. Phase 5 runs after each phase and at the end.

Wiring steps that are easy to miss: register the route in `isBuilderRoute` and the construction in `cmd/ai-manager/main.go` (security-relevant: the input must never be logged, pinned by `Test_processFlowBuilder_neverLogsTheInput`); front round-trip test `flowDraftRoundtrip.test.js` for branch shapes; `ConfirmDialog` for replacing editor content.

Design decisions carried into the plan: no branching on action type names in builder code (everything derives from `Meta`); fail-closed drift locks (`Test_EveryUUIDFieldIsTagged` detects nested reference types; `Test_BuilderExcludedTypesAreInTypeListAll` pins the two excluded types but does not detect new ones by itself); classification-based exposure; `internal` types are ai_summary, block, confbridge_join, echo, external_media_start, external_media_stop, fetch, goto, mute, stream_echo, transcribe_stop; `call` and `email_send` are excluded structurally by `BuilderExcludedTypes` (nested `[]Action` and `[]Attachment` that the ref tags cannot reach, pinned by `Test_BuilderExcludedTypesAreInTypeListAll`); `sensitive_nodes` set by code; 13 warning keys (12 constants in `flowbuilder/main.go`, plus `draft_discarded` from `builderhandler/parse.go`) shared by back and front; separate daily counter (OQ7); queue-level circuit breaker coupling accepted with timeout metrics (OQ10).

Values shipped unmeasured (the evaluation harness would have set them): `MaxFlowNodes=60`, `flowDefaultMaxOutputTokens=8192` (`flow_turn.go`), the LLM timeout, the 512KiB body limit, and the timeout ratio behind OQ10. A follow-up ticket measures them.

Design section 8 differences: the fixed 'assistant builder' wording is generalized through the `noun` parameter of the shared `mapBuilderRPCError` in api-manager, not in `chat.go`; `listenhandler/models/request/builder.go` is part of the diff.

Planned versus done: the evaluation harness (design section 9) is deferred to a follow-up and is listed as such in the PR. Mutation checks, real-browser checks and the eight-scenario replay were performed by the review rounds (evidence is in the round reports, not in the repository) with throwaway tests under /tmp and are not committed.

## Test strategy

TDD per unit; contract tests pin catalog statements to executor facts (`Test_FlowCatalog_*`); committed parser and validator tests: table-driven `Test_FlowParse` (mostly normal and boundary inputs), `Test_ReconstructGraph`, individual adversarial cases in `flow_transcode_test.go` (for example control characters in a label, `Test_AssembleFlowDraft_caseVariantKeysCannotCarryReferences`, `Test_ReconstructGraph_caseVariantKeysAreNotShownToTheModel`, `Test_AssembleFlowDraft_addressTargetOfAResourceTypeIsCleared`) and five `Test_ValidateDraft_*` tests. Randomized input against the parser (about 30,000 cases) was run by a review round with a throwaway test and is not committed. Front Flow store transitions are tested without fake timers; the timer behavior lives in the shared factory and is covered by the Assistant store tests with fake timers, which pass unchanged.

## Rollout and risk

Deploy order: bin-common-handler and bin-flow-manager, then bin-ai-manager, then bin-openapi-manager and bin-api-manager, then the front (the front calls the new route, so it goes last). Rollback order is the reverse: hide the front entry first, then revert the backend. The Flow daily counter keys (`ai:flow_builder:chat:count:<customer>`) stay in cache after a rollback until they expire. Flow and Assistant share the LLM concurrency semaphore (`Test_FlowChat_sharesTheSemaphoreWithTheAssistantBuilder`), so heavy Flow traffic can make Assistant requests answer `BUILDER_BUSY`; this is an intended trade-off for v1.

Behind the existing builder availability status (`GET /ai_builder/status`): when the builder key is not configured, `flow_chat.go` returns Unavailable and the front hides the entry card. The switch is shared with the Assistant Builder, there is no Flow-only flag (by design; a new on/off flag was not requested). No schema migration. This PR also changes shared Assistant-side code (the `builderhandler.NewBuilderHandlers` constructor (it returns both handlers; `cmd/ai-manager/main.go` is the caller), `isBuilderRoute` and panic handling in `listenhandler/v1_ai_builder.go`, the shared `mapBuilderRPCError`, the front `createBuilderStore` factory and `BuilderPanel`, and catalog text), so the safe rollback is reverting the whole PR pair, not only the route and the entry card. The shared catalog (`actioncatalog`) is also consumed by the runtime AI tools (`describe_action`, tool definition enums), so Required flags and descriptions changed there reach live AI calls too. Other shared changes: `bin-flow-manager/models/action/option.go` (tags and comments on every option field), `bin-common-handler/models/address` (new function), front `builderApi.js` (`sendChat` takes `endpoint` and `extra`), front `resourceCacheStore.js` (`clearAllResourceCaches` also clears the Flow session key). Metrics added for timeouts and circuit opens to measure the queue-level circuit breaker coupling.
