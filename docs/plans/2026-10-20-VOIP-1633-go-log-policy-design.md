## 3. Change

Level (both services, existing Cobra and Viper convention, no on/off flag):
- Flag and env `log_level` / `LOG_LEVEL`, default `info`. `initLog` sets Info. A function `applyLogLevel(value string)` accepts `debug`, `info`, `warn`, `error` (trimmed, case-insensitive) and sets the global level; it is called first in `LoadGlobalConfig`, before its Debug line. An unknown value keeps Info and logs one Warn that lists the allowed names. The function is separate from the `sync.Once` so tests call it directly.
- `ai-control` and `pipecat-control` share Bootstrap, so their default level also becomes Info (intended).
- Operations note: `LOG_LEVEL=debug` in the Go service `environment:` of the compose file turns Debug on; the Python runner containers are not affected. Compose files stay unchanged.

Lines:
- G1/G6: log `method`, `uri`, `data_len` (request) or the id the message already names plus `data_len`; G2: `publisher`, `type`, `data_len`.
- G3/G4/G5: drop the struct dump; keep the ids the message text already carries and add lengths where useful (`content_len`, `llm_message_count`, `text_len`). Fix the wrong `message_id` value at `start.go:402`.
- No new helper package. Edits are at the call site.

## 4. Verification plan

- RED first: log capture tests on the unmodified code with a sentinel sentence, then the same tests after the change. Hook captures every entry (message, fields rendered with `%v` and JSON) at Debug level and asserts the sentinel is absent and the expected keys (`aicall_id`, `pipecatcall_id`, `data_len`, `content_len`) are present (acceptance 4). Paths: pipecat TextFrame, TranscriptionFrame, received raw frame, "Created pipecatcall" (Info), listen request for message create, response marshal failure (Error), subscribe event for a pipecat message, messagehandler event, DTMF, tool arguments, the input websocket and the python runner error. The summary content and request paths are guarded by the source scan only (no capture test).
- Feasibility of the capture paths: pipecat TextFrame and TranscriptionFrame go through `RunnerWebsocketHandleOutput` with the existing mockable `websocketHandler` (`ReadMessage` returns a proto frame, then an error); "Created pipecatcall" through `startReferenceTypeCall`-style mocks as in `start_test.go`; the G6 marshal failure is induced in ai-manager by a `chan` value in `AIcall.Metadata` (a `map[string]any`) returned from the mocked handler, and for pipecat (no failing field) it is covered by the scan test only. If the websocket path is too costly, the log call is moved into a small function and tested directly. `TestBootstrap` flag assertions are updated for the new flag. RED output of the capture tests on the unmodified code is kept as card evidence.
- Source scan test per service (go/ast, no type information, no new dependency), applied to every log call regardless of level. Rules: `WithField`/`Fields` keys from the audited set (`request`, `event`, `message`, `aicall`, `pipecatcall`, `summary`, `content`, `session`, `frame`, `response`, `variable`, `tool_arg`, `tool_call`, `request_content`, `pipecat_message`, `conversation_message`, `function`, `answer`, `ai_call`) fail unless the value expression is in an explicit allowlist; format arguments ending in `.Content`, `.Text`, `.Data`, `LLMMessages` or named `tmp`/`res`/`m`/`evt`/`message` passed to `%v`/`%s` fail unless allowlisted. Scope: non-test, non-vendor, non-mock files. Format arguments are matched to their verb (`%d` arguments such as frame ids pass). The audited key list is deliberately narrower than the kept list (`team`, `transcribe`, `call`, `external_media`, `event` of runner.go:574 are not audited). The scan also refuses `SetLevel` outside `internal/config`, and `logtest` has its own self test. Limits: names are syntactic, field maps built in a variable (`fields := logrus.Fields{...}`), constant keys, `Debug(m)` without a format string and `String()` indirection are not seen, so a renamed variable is missed; this is why the capture tests are the proof and the scan is the regression guard. The allowlist is one map in the test file and every entry needs a reason; false positives (an id field named `.Data`, error objects) go there.
- Level tests call `applyLogLevel` directly: default Info does not emit Debug; `debug` emits; invalid value keeps Info and warns. Tests restore the logrus level, output and hooks in `t.Cleanup` and do not use `t.Parallel`.
- `go mod tidy && go mod vendor && go generate ./... && go test ./... && golangci-lint run` in both services. Service docs `docs/operations.md` config table gets `log_level`.
