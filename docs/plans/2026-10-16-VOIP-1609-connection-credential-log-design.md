# VOIP-1609: stop logging RabbitMQ credentials and remaining DSN log paths

## 1. Ticket review (result: valid, one part extended)

Checked against origin/main 0541a6e93.

- Confirmed: `bin-common-handler/pkg/rabbitmqhandler/main.go` writes `"url": r.uri` in `Close()` (Info, line 189) and in `connect()` (line 241: "Connecting to rabbitmq" Debug, the connect error `Errorf`, "Connection established to rabbitmq." Debug). `r.uri` is the full `amqp://user:password@host` string handed over by `sockhandler.NewSockHandler`. Every service that uses `sockhandler` is affected.
- Not found: an open or merged PR for the same topic (`gh pr list --state all`), earlier fix commits in `git log -- rabbitmqhandler/main.go`.
- Extension found while checking the error paths the ticket lists as candidates: reproduced with a sentinel password, a malformed address makes `net/url` embed the whole raw address (userinfo included) in the error text.
  - `amqp.Dial("amqp://user:SENTINEL@host:99x/")` returns an error that contains SENTINEL (any `url.Parse` failure leaks the whole address: a bad port, a bad `%zz` escape in the path or inside the password). A well formed address that cannot be reached returns only `dial tcp <ip:port>: connect: connection refused`.
  - `lib/pq` `Ping()` with a malformed `postgres://` DSN behaves the same, and so does `migrate.New` (golang-migrate v4.19.1): the postgres driver `Open` and the source driver call `url.Parse` and put the raw URL in the error, and `SchemeFromURL` returns everything before the first `:` as the scheme, which `unknown driver` then prints, so a keyword style DSN (`... password=SENTINEL:x ...`) leaks there too even though `pq` accepts it.
  - The error reaches the log in four places: `rabbitmqhandler.connect()` (`Errorf`, retried every second), `bin-trigger-sender` `run()` (`dial RabbitMQ: %w`, logged by `main`), `bin-rag-manager` `runMigrations()` (`failed to initialize migrate: %w`, returned by `run`, runs before `runService`) and `runService()` (`could not ping PostgreSQL: %w`).
  - The leak checks use `strings.Contains` booleans (the terminal masks password-like text).

## 2. Candidate paths and decision

Search: `amqp.Dial`, `sql.Open`, `clickhouse.Open`, `redis.NewClient`, `ParseDSN` and `ParseURI` over `bin-*` and `voip-*` (excluding vendor, tests, mocks); `WithField("config"` and `cfg` passed to log calls (none left after VOIP-1602); log or error calls that format `dsn`, `uri`, `addr`, `password`, `RabbitMQAddress`.

| Path | Decision | Evidence |
|---|---|---|
| rabbitmqhandler `Close()`, `connect()` url field | fix | above |
| rabbitmqhandler `connect()` dial error | fix | malformed address leaks |
| bin-trigger-sender `run()` dial error | fix, local to the service | the module does not import bin-common-handler |
| bin-rag-manager `migrate.New` and `sql.Open` + `Ping` errors | fix, local to the service, one gate before both | malformed DSN leaks in both |
| bin-timeline-manager `runMigrations` `"dsn": ClickHouseAddress` | exclude | the value is only host:port: `clickhouse.Options.Addr` takes `[]string{address}` with no userinfo, the flag help says "ClickHouse server address", the migrate dsn is built as `clickhouse://<address>/<db>`; no credential field exists |
| `bin-schedule-manager` `backuphandler` `ParseDSN` (`backup.go:47`) | exclude | already safe: on failure it returns a fixed text without the DSN |
| `databasehandler.Connect`, `migrationhandler` | exclude | go-sql-driver `ParseDSN` errors print only a parameter value or the dbname, never the userinfo position; a leak needs a pathological password that contains `/` and no database path (reproduced by the reviewer), which the configured DSN format does not have |
| redis clients (`cachehandler`, 30+) | exclude | options structs, no URL string; go-redis dial errors name only the address |
| flag help strings with an example `amqp://guest:...@localhost` | exclude | documentation of the well known default, not a secret |

## 3. Design

- rabbitmqhandler: one unexported helper in `main.go`, `uriHost(uri) (host string, valid bool)`: `url.Parse(uri)`, host `""` and valid false when parsing fails.
  - `connect()` calls it once before the loop. When `amqp.Dial` fails and `valid` is false, the error that is logged is the fixed `invalid rabbitmq address format` instead of the dial error. `amqp.Dial` starts with `url.Parse`, so the parse failure is the only way the text carries the address; the other errors in amqp091 `uri.go` (`errURIScheme`, `errURIWhitespace`, port and query number errors) and `DialConfig` are constants or contain only a query value (a number or `auth_mechanism`), and the query carries no credential. Verified with a reproduction: huge port, whitespace, `http://` scheme and `heartbeat=x` do not leak.
  - `Close()` and `connect()`: the `"url": r.uri` field becomes `"host": host` (`Close()` calls the helper too). Messages and levels stay. Not logging the host at all was rejected: the host tells which broker a replica talks to.
- bin-trigger-sender: before `amqp.Dial`, return `errors.New("invalid RabbitMQ address format")` when `url.Parse(rabbitAddr)` fails.
- bin-rag-manager: a function `validatePostgreSQLDSN(dsn)` in `cmd/rag-manager/main.go`, called at the top of `runMigrations` right after its empty DSN skip (`cfg.Validate()` already rejects an empty DSN, so the skip stays as is). Standard library only. The DSN must start with the literal prefix `postgres://` or `postgresql://` (case sensitive, the two schemes registered by the golang-migrate postgres driver; `pq` also decides URL or keyword style by this prefix), and `url.Parse` must succeed; otherwise it returns `invalid PostgreSQL DSN format` without the cause. Why this closes the paths: `runMigrations` runs before `runService` in `run()`; with the prefix, `migrate.New` and `pq` both treat the value as a URL and parse it with the same `url.Parse` that the gate already passed, so no parse error text exists; the opaque form (`postgres:user:SENTINEL@host/db`) passes `url.Parse` and a scheme check but is read by `pq` as a keyword DSN, whose error prints the whole string, so the check is on the literal prefix `//` form, which also makes `Opaque` always empty (no separate check); upper case schemes, a leading space and control characters are rejected by the prefix or by `url.Parse`. The errors that remain after the gate print query parameter values (`x-*` of migrate, `sslmode`, `connect_timeout`, `target_session_attrs` and similar of `pq`) and host or connection text; the userinfo and a `password` query are never printed (about 190 adversarial inputs checked by the reviewers). Keyword style DSNs are rejected, which loses nothing: `migrate.New` already refuses them at startup today. The gate lives in `runMigrations` so that a test can call it directly.
- Known limit of `uriHost`: an unescaped `/` inside a password (`amqp://u:12/ss@host`) parses and puts `u:12` in the host field; such an address is already invalid for the broker and is not guarded.
- No new shared package, no config flag, no change to log messages or levels.
- Rollback: revert the commit (log text and one error text only).
- Triggered workflows: the mapping is in `.circleci/config.yml` (path-filtering). `bin-common-handler/.*` maps only to `run-bin-common-handler`, whose workflow runs `bin-common-handler-test` (`config_work.yml` around line 388). No dependent service is built or tested by CI for this change, so the local build and test run of every dependent service (section 4) is the only guard against a regression, and the fix reaches each service when that service is next built. `bin-rag-manager/.*` and `bin-trigger-sender/.*` map to their own workflows. trigger-sender has no release job (CronJob pulls `:latest`).

## 4. Tests (written together with the code)

- rabbitmqhandler `Test_uriHost`: `amqp://user:SENTINEL@broker.example:5672/` yields host `broker.example:5672` and valid; the malformed `amqp://user:SENTINEL@broker.example:99x/`, `amqp://user:SENTINEL@broker.example/%zz` and `amqp://user:SENTINEL%zz@broker.example/` yield valid false (all three leak the whole address in the old dial error, so the old code fails the connect test below).
- rabbitmqhandler `Test_connect_no_credentials`: a collecting logrus hook (a small `captureHook` in the test file, no new dependency) replaces the hooks of the standard logger and sets the level to Debug; `t.Cleanup` restores both. `connect()` runs in goroutines against `amqp://user:SENTINEL@127.0.0.1:1/` (refused, so the retry loop logs "Could not connect") and against the three malformed addresses. The test waits for the error entry of the refused address (it must contain the host `127.0.0.1:1`) and for an error entry with the fixed text, then asserts that no collected entry (message and fields) contains SENTINEL. The retry goroutines are not stoppable (`connect()` does not check `closed`; changing that is outside the ticket) and end with the test process; later runs may therefore be satisfied by entries of earlier runs, which only loosens the waits and widens the SENTINEL check. Separate test `Test_Close_no_credentials`: `Close()` on a rabbit built with the existing mock connection logs the host without SENTINEL. The tests are also run with `-race -count=5`.
- trigger-sender: `run()` with the malformed address returns an error without SENTINEL (old code compiles and fails).
- rag-manager `Test_runMigrations_dsn_no_credentials`: the test calls `t.Chdir("../..")` first, because `runMigrations` opens `file://./migrations` relative to the cwd and `migrate.New` opens the source before the database URL (without the directory the error never contains the DSN, even in the old code, and the test would not be RED). The password `SENTINEL%zz` is the only thing that makes the second DSN unparsable; a code comment says so, so that nobody tidies the value and loses the RED. `runMigrations` with `postgres://user:SENTINEL@db.example:99x/db`, `postgres://user:SENTINEL%zz@db.example/db`, the keyword DSN `host=db.example password=SENTINEL:x` and the opaque `postgres:user:SENTINEL@db.example/db` returns the fixed error and no SENTINEL (old code fails behaviourally: the `migrate.New` error contains SENTINEL). `validatePostgreSQLDSN` direct cases: a valid `postgres://` and `postgresql://` URL return nil. The call site inside `run()` is covered only by `runMigrations` running first in `run()`; a test of `run()` itself needs the cobra command and is not added.
- RED proof: the behavioural tests (connect log, Close log, trigger-sender run, rag-manager runMigrations) compile against the old code and must fail there; `Test_uriHost` tests a new helper and is only compile level RED. Run on a scratch copy of the old code.
- Verification: `go mod tidy && go mod vendor && go generate ./... && go test ./... && golangci-lint run -v --timeout 5m` for bin-common-handler, bin-trigger-sender, bin-rag-manager, and `go build ./... && go test ./...` of all services that vendor bin-common-handler.
