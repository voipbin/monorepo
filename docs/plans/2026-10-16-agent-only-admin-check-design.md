# VOIP-1607 agent-manager: only-admin check design

## 1. Ticket review
Valid. `isOnlyAdmin` (bin-agent-manager/pkg/agenthandler/agent.go) reads only the first 1000 agents of the customer (`AgentList` orders by `tm_create DESC`). A customer with more than 1000 agents whose other admin is older than the newest 1000 gets "sole admin", so Delete and UpdatePermission are refused. Lookup errors also return "sole admin". Delete returns a plain error (listenhandler `errorResponse` -> 500); the permission PUT maps every error to a reasonless 400. `isOnlyAdmin` callers: Delete and UpdatePermission only. `Delete` callers: listenhandler and `agent-control` (prints the wrapped error, no behaviour dependency); the Delete error contract changes 500 -> 404/409/400. `UpdatePermission` callers: listenhandler only (agent-control uses `UpdatePermissionRaw`, customer creation uses `Create`). The customer-deleted event handler (event.go) also lists only 1000 agents and leaves the rest orphaned; outside this ticket, reported separately.

## 2. Change (agenthandler never imports listenhandler DTOs)
1. `isOnlyAdmin(ctx, id) (bool, error)`. Errors are returned, not folded into true. The `Get` error is returned unwrapped so a typed NotFound (404) survives; list errors are wrapped with `pkg/errors` `Wrap` (chain kept, unclassified -> 500). `Delete` and `UpdatePermission` deny on error (fail-safe stays) and return the error as is.
2. Other-admin search pages through the customer's non-deleted agents: page size constant 1000, first page token `""` (existing mocks keep `AgentList(ctx, uint64(1000), "", filters)`), later pages: token = `last.TMCreate.UTC().Format(utilhandler.ISO8601Layout)`, stop at the first other CustomerAdmin or ProjectSuperAdmin, or when a page is shorter than the page size. Nil `TMCreate` on the last row of a full page (a next token is needed) is an error (fail-safe). No repeated-token guard: the query is `tm_create < token` with DESC order, so the token strictly decreases and the loop ends.
3. Real sole admin: `cerrors.FailedPrecondition(agent-manager, "AGENT_LAST_ADMIN", ...)` -> 409, from Delete and UpdatePermission, returned without an extra wrap.
4. `processV1AgentsIDPermissionPut` uses `errorResponse(err)` instead of `simpleResponse(400)`. To avoid a 400 -> 500 regression, the guest-agent rejection in `UpdatePermission` becomes `cerrors.InvalidArgument(agent-manager, "AGENT_GUEST_IMMUTABLE", ...)` (400). DB write failures in the permission PUT change from 400 to 500 (correct for a server fault), and a missing agent (`Get` or `dbUpdatePermission` NotFound) from 400 to 404; api-manager checks the agent first, so this is an RPC contract change that is rarely reached. Unmarshal errors stay 400. Delete's guest rejection uses the same typed error (500 -> 400) so both paths answer alike. Delete behaviour changes too: missing agent 500 -> 404 (typed NotFound preserved), sole admin 500 -> 409.
5. OpenAPI: add `'409': Conflict` (existing component) to DELETE /agents/{id} (paths/agents/id.yaml) and PUT /agents/{id}/permission (paths/agents/id_permission.yaml); `go generate` in bin-openapi-manager and bin-api-manager.
6. Docs: `AGENT_LAST_ADMIN` (409) and `AGENT_GUEST_IMMUTABLE` (400) rows in `restful_api_errors.rst` Agent Reasons, one new sentence in `agent_overview.rst` near the existing admin remark (the last-admin guard answers 409), clean rebuild of HTML, `git add -f` build.

## 3. Not changed
dbhandler (permission is a bitmask, equality filters cannot express "another admin"; a new query would widen the interface and mock), other services (no `isOnlyAdmin` pattern in bin-*), sole-admin semantics (downgrade to anything other than CustomerAdmin is still refused).

## 4. Tests (RED first, via public methods so the pre-fix code fails at runtime, not at compile time)
- Delete and UpdatePermission with 1000 + n agents, other admin only on page 2 -> allowed. The second `AgentList` call must carry the exact token of page 1's last `TMCreate` (no `gomock.Any()`).
- Real sole admin -> `errors.As` VoipbinError, FailedPrecondition, reason AGENT_LAST_ADMIN, for both methods; strengthen the existing "only admin error" (agent_additional_test.go) and "downgrade only admin" (agent_test.go) assertions.
- Page of exactly 1000 without admin followed by an empty page -> sole admin; two pages where the last row of page 2 is the target itself -> sole admin; nil `TMCreate` -> error; list error -> denied, `errors.Is` the sentinel, not AGENT_LAST_ADMIN (characterization); Get NotFound -> typed 404 preserved.
- Existing tests changed: `Test_isOnlyAdmin` (`res, err :=`, `expectErr`); `Test_UpdatePermission_error` "not found" (agent_test.go) returns `dbhandler.ErrNotFound` instead of `fmt.Errorf` and asserts the typed 404. The expected second-page token is a literal string, not recomputed with `Format`. Only listenhandler permission PUT 409/404/500 cases are RED before the fix (via `responseErr`); the 400 cases, Delete mappings and the list-error case are characterization tests, not claimed as RED. New test functions use the `Test_` prefix and `mc`; existing function names are not renamed.
- listenhandler: `Test_processV1AgentsIDPermissionPut` and Delete table cases for 409/404/500 and 400 (unmarshal error, guest).
- Run `scripts/check-test-conventions.sh`, the full verification workflow in bin-agent-manager, build and tests in bin-api-manager and bin-openapi-manager.

Fail-before-fix check: the new public-method tests are run on the unmodified code (the `isOnlyAdmin` signature change is not yet applied); mock call counts are fixed explicitly (a full last page costs one extra empty-page call); the listenhandler guest-400 case checks the mapping only, not the real guest path.

## 5. Risks
Timestamp ties at a page boundary could skip an agent created in the same microsecond; the result is a deterministic wrong refusal for that case (fail-closed, not a wrong allow), probability negligible at microsecond precision, same property as the existing list pagination. Behaviour change: permission PUT sole-admin 400 -> 409, DB failure 400 -> 500. Existing limit left as is: concurrent mutual deletion of two admins (TOCTOU).
