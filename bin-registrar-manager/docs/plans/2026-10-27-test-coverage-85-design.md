# bin-registrar-manager test coverage 85% (VOIP-1659)

## Goal and baseline
Raise the hand-written statement coverage (excluding files under `gens/`, `mock_*.go` files and files whose header before `package` has `Code generated` and `DO NOT EDIT`; duplicate profile blocks are merged by their maximum count; measured from `go test -coverprofile` output) from 84.45% (3089/3658) to at least 85.5% (3128 statements, +39). Only test files are added. No product code, signature or exposure changes.

## Approach and expected gain (statements, measured on scratch copies or counted from the uncovered-block report)
1. `cmd/registrar-control` (+85 measured with exactly this design on a scratch copy; at least +65 even without the rollback and `--execute` cases): call `RunE` of the 10 extension and trunk commands, `domain-migrate` (dry-run and `--execute`) and `domain-migrate-rollback` directly (never `Execute`, so `config.Bootstrap` is not run), with valid flags and `config.Get().DatabaseDSNBin` set to the slash-less string `nonsense-dsn`. The MySQL driver rejects it while parsing the DSN inside `sql.Open`, so the first `Connect` of the init functions fails with no network access, before any asterisk, cache or RabbitMQ wiring. Assertions: the exact outer text (`failed to initialize handler` for the 10 commands in `main.go`, `failed to initialize handlers` for the two migration commands) and the inner text `could not connect to bin database` with `database open error` (so a fallback to a network attempt fails the test). The log file of `--execute` and rollback is created under `t.TempDir()`. The three init functions are also called directly. Each command test asserts both texts, so removing the wrapping of any single command fails that command's case. Statements before the init call (update option mapping, allowed-ips splitting, flag checks) become covered; their results are not observable before the init call, so they are covered only as a side effect (the only observable property is that the flow reaches the init error, which the assertion checks) and they are not mutation targets. Rollback needs the log file to exist before the init call (an empty file under `t.TempDir()` is valid), and `--execute` cases assert that the log file was created. List filters and trunk auth types sit after the init call and stay uncovered.
2. `NewContactHandler`, `NewExtensionHandler`, `NewTrunkHandler` (+12): inject distinct mock dependencies, assert the concrete returned type and that every field is the same instance that was injected (`==`).
3. `models/common` (+3): the extension accessor and the trunk accessor each panic when uninitialised (`recover()` value asserted as `*logrus.Entry` with the expected `Message`); a domain made of valid short labels joined by dots, longer than 253 characters, is rejected (the regular expression alone would accept it, so this case isolates the length check).
4. `pkg/dbhandler` (+12, go-sqlmock; the cache helpers `customerDomainSetToCache` and `customerDomainDeleteFromCacheByRealm` are called directly in the package test because their callers drop the error): helper errors (2); generic exec failure of `CustomerDomainUpdate` (1, the duplicate branch is already covered); `row.Err` in `extensionGetFromDB`, `trunkGetFromDB`, `SIPAuthGet` (3); `rows.Err` in `ExtensionList` and `TrunkList` (2); empty token in `ExtensionList` (1); unsupported filter type rejected by `ApplyFields` in `ExtensionList`, `TrunkList`, `CustomerDomainList` (3).
5. `pkg/listenhandler` (+3): the extension-number lookup (`/v1/extensions/extension/<value>`) with a malformed escape (`%zz`) through `processRequest` returns a 400 `sock.Response` and a nil error (+1); `errorResponse` with a typed nil `*VoipbinError` returns 500 (+2). The other uncovered listenhandler blocks are `json.Marshal` failures and are excluded.
6. `cmd/registrar-manager` (+up to 23): `runListen` and `runSubscribe` take interfaces and are tested with the generated mock sock handler. `runListen`: queue creation failure returns nil (error swallowed) and the expected queue name is asserted; success path asserts the consume call on the request queue. `runSubscribe`: failure at `QueueCreate`, at topic creation and at `QueueBind` each return the error and `ConsumeMessage` is not expected; success path asserts the queue name, the event exchange and one bind per pattern of the subscribed pattern list. The goroutines of the success paths are awaited through a channel closed in `DoAndReturn` (exact mocked signature) with a `select` timeout, before the test ends; the consume callback argument is matched with `gomock.Any()`. `main`, `runDaemon`, `run`, `initCache` and `initSignal` are excluded (process-wide side effects or external connections); the new tests do not call `initProm` (the existing test of it keeps its own path).
Items 1 to 5 give about +95 at the item 1 minimum (65+12+3+12+3), +115 with the measured item 1; item 6 adds up to +23. Required: +39 (the sum is about 87%). Fallback if the final measurement is below 3128: the remaining reachable error branches in the uncovered-block report.
Every new test asserts a concrete error text, return value or recorded call; tests that only call a function, or recompute the expected value with the code under test, are not allowed.

## Isolation
No `t.Parallel`. `config.Get()` returns `&globalConfig` (checked in the code); tests set the single field in place, never replace the pointer, and restore the saved value in `t.Cleanup`. viper is reset with `t.Cleanup(viper.Reset)` and flags are bound as in `Test_runCommands_validation`. The panic tests call the base-domain reset helper first and in cleanup (the helper returns the state to uninitialised and does not restore a previous value, so no test of the package may depend on it being set). Values are synthetic (no `user:pass@host` strings), no sockets, no clock dependence.
