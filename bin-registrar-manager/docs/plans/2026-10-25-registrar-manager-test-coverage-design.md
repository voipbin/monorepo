# bin-registrar-manager unit test coverage (VOIP-1652)

## 1. Ticket review

Verdict: valid.

- Baseline re-measured on origin/main accc03e with `GOFLAGS=-mod=mod go test -count=1 -coverprofile=cp.out ./...`: hand-written statements 3658, covered 2724, 74.47%. Generated code and mocks are excluded (path `/gens/`, file name `mock_*`, header with `Code generated` and `DO NOT EDIT`), duplicate blocks are merged with the max count. The number matches the card (74.5%). All existing tests pass.
- The card does not name a target higher than 75.0%, and recommends 76% or more. 76% needs 2781 covered statements (3658 x 0.76 = 2780.08), so at least 57 more.
- Not testable without live services: `cmd/registrar-manager/main.go` (148 uncovered, daemon wiring to RabbitMQ, Redis and two databases) and the `init*Handler` functions and the second half of each `run*` function in `cmd/registrar-control/main.go` (they open database, cache and broker connections). These are left alone.
- Testable without live services: in `cmd/registrar-control/main.go`, `initCommand` (L43) and the ten `cmdExtension*` and `cmdTrunk*` constructors only build `*cobra.Command` values with flag definitions (L223, 272, 302, 355, 414, 448, 514, 544, 597, 668). Each `run*` function validates its flags with `resolveUUID` and `resolveString` before it calls an `init*Handler`, so the validation failure branches (failure branches only; a passing validation proceeds to a connection) return before any connection is made (for example `runExtensionCreate`, L240-L251; the get, list and delete commands have a single such branch). Measured: the ten constructors hold 153 uncovered statements and `initCommand` holds 74, of which the `PersistentPreRunE` closure (L47-L52, hook at L47) and the migrate command closure (L78-L81) do not run when the command tree is only built; the validation failure branches add a few more. About 200 statements in this file are reachable without live services.
- Product code is not changed. No test hook, signature or visibility change is needed: every target below is reachable through existing unexported functions from in-package tests, or through gomock and sqlmock.

## 3. Design

Test files only, all under `bin-registrar-manager/`. Each test asserts an observable outcome (returned error and its cause, calls that must not happen, state handed to the next collaborator). No self-comparing tests, no `t.Parallel`, no network. Conventions: `Test_` prefix, gomock controller named `mc`, standard `testing` only (the CI gate `scripts/check-test-conventions.sh` is run before push). Test imports are limited to what `go.mod` already lists as direct dependencies: cobra API (`cmd.Flags().Parse`), viper, logrus and `logrus/hooks/test`, sqlmock, gomock. No `pflag` or `prometheus/client_model` import (both are indirect); `go mod tidy` must leave `go.mod` and `go.sum` unchanged.
