# bin-registrar-manager test coverage 90% (VOIP-1663)

## Goal and baseline
Raise the hand-written statement coverage (excluding files under `gens/`, `mock_*.go` files and files whose header before `package` has `Code generated` and `DO NOT EDIT`; duplicate profile blocks merged by their maximum count; measured from `go test -coverprofile`) from 88.35% (3232/3658) to at least 90.5% (3311 statements, +79); the target is 91% (3329, +97). The baseline moves by one statement between runs because one consume goroutine branch depends on timing. Only test files are added. No product code, signature or exposure changes.

## Approach (statements are estimates from the uncovered-block report)
The start paths could not be tested before because they open real connections. `bin-common-handler` now has replaceable factories (`sockhandler.SetRabbitFactory`, `databasehandler.SetConnectFunc`, `migrationhandler.SetEngineFunc`) that return a restore function. The tests use them with a go-sqlmock database, a fake migration engine, the generated `MockSockHandler` (with `Connect` and the topic creation as expected calls) and a miniredis server on a loopback port. Creating the request handler registers Prometheus collectors with no duplicate guard (a second call in one process panics), so the same helper also replaces `prometheus.DefaultRegisterer` with a fresh registry for the duration of the test and puts the old one back in cleanup (`DefaultGatherer` stays as it is); at least two success cases per package therefore run in one process.
1. `cmd/registrar-control` (about +190): a shared test helper installs the three factories and the cache address and restores everything in `t.Cleanup`. Then `initCache`, `initExtensionHandler`, `initTrunkHandler` and `initDomainMigrationDeps` are tested for success and for each failing step; the extension and trunk commands run past the init call with the database returning an error or a row, asserting the wrapped error text or the printed JSON (stdout captured through a pipe, restored in cleanup); `domain-migrate` (dry-run, `--execute`) and `domain-migrate-rollback` run to completion on empty data; the `migrate` subcommand factory and the root `PersistentPreRunE` success path run once with synthetic domain names (base-domain state reset before and after); `parseMigrationLog` gets a reader that fails mid-read; the resume branch of the customer migration gets a row with a short label. Commands are always run with explicit arguments, never from `os.Args`.
2. `cmd/registrar-manager` (about +115): `runDaemon` for each failing step (bin connect, migration, asterisk connect, cache, subscribe start) and for the full path ended by a token put into `chDone` beforehand; `run` success and subscribe failure with the mock sock handler (the request and event consume goroutines are both awaited through closed channels before the test ends, and the topic creation expectation, called by the notify handler and again by the subscriber, is set for both calls and always returns nil); `initCache` success and failure (miniredis closed); `initSignal` by sending a value into `chSigs` and receiving from `chDone` with a timeout (no real OS signal); every `runDaemon` test sets the metrics endpoint to a path that is unique per call (atomic counter, never `/metrics` and never empty) and the listen address to `127.0.0.1:0` (an empty address would bind a fixed port), restored in cleanup; `initProm` failure by an invalid listen address, observed through a logrus test hook that is removed again in cleanup, with a unique handler path per call so `http.DefaultServeMux` never sees a duplicate (the path `/metrics` of the existing test is not used).
3. Small package gaps (about +10): the consume failure log branch of `subscribehandler.Run` (awaited), `PrepareFields` errors of the four update functions in `pkg/dbhandler` (a value that cannot be encoded inside a map), the encoding failure of the cache setter.
Required: +79. The sum of 1 and 2 alone is above it, so item 3 and any single failing case do not decide the result. The command functions are tested one by one; the two `main` functions are not called.

## Isolation
The config fields are always set directly on `config.Get()` (never through the environment, because the singleton loads only once); a shared helper first runs the bootstrap path once (with the domain-name environment variables pinned by `t.Setenv` to synthetic values so a developer shell cannot change the result), then saves and restores the logrus formatter, level and output that it changes and the viper state. the registry replacement is also global state; `signal.Stop(chSigs)` and a non-blocking `chDone` drain (also covering tokens written by goroutines left from earlier tests) run in cleanup of every test that starts `initSignal`. No `t.Parallel` in any test that touches a factory, `config.Get()`, viper, logrus hooks, `chSigs` or `chDone`. Config fields are changed in place and restored in `t.Cleanup`; the config singleton is consumed once by a shared helper before fields are set so test order does not matter. The base-domain state is reset before and after the tests that need it. `chDone` is drained before and after each start test and the signal test receives from it with a timeout. Only loopback listeners (miniredis, port 0 or an invalid address), `t.TempDir()` files and synthetic values are used; no `user:pass@host` strings, no fixed ports, no host paths, no network.

- `go mod tidy && go mod vendor && go generate ./... && go test ./... && golangci-lint run -v --timeout 5m`; `go.mod` and `go.sum` unchanged (go-sqlmock and miniredis are already required); coverage with `GOFLAGS=-mod=mod go test -count=1 -coverprofile`, covered hand-written statements at least 3311.
- Flaky check: `go test -race -count=3 -shuffle=on` on the touched packages, plus a run with the bootstrap test and the existing `Test_initProm` forced first and last (the `-run` order and shuffle seeds used are listed in the review notes).

- Every new test asserts a concrete error text, printed value, return value or recorded call; tests that only call a function are not allowed.
- `git diff --stat origin/main...HEAD` lists only files under `bin-registrar-manager/`.
