# VOIP-1657: bin-contact-manager unit test coverage to 80%

## 1. Ticket review (analysis)

Baseline (origin/main 161e974, `GOFLAGS=-mod=mod go test -count=1 -coverprofile`): hand-written 2954/3831 = 77.11%, raw 2954/4435 = 66.61%. Generated code is excluded by path (`/gens/`, `mock_*.go`) and by the `Code generated ... DO NOT EDIT` header; duplicate blocks are merged with the maximum count. The ticket figures reproduce exactly, and no commit touched this service between the ticket baseline and origin/main. Earlier coverage work on this service is merged and part of the baseline; no open PR touches this service.

Uncovered hand-written statements (877): cmd/ 489 (contact-control 325, contact-manager 148, case-control 16), pkg/dbhandler 250, pkg/listenhandler 93, pkg/contacthandler 20, pkg/casehandler 17, others 8. Reaching 80.0% needs 111 more covered statements (3065), 80.5% needs 130 (3084). The reachable upper bound is well above 80%, so no block is needed.

## 2. Plan

Tests only, inside bin-contact-manager. No non-test file changes, no new modules (sqlmock and miniredis are already in go.mod). Floor 80.0%, recommended 80.5%, target at least 81% (about 150 new statements) with assertions on behavior. Work order is B, C, D, then A only for the shortfall, so the number is not carried by constructor-only tests.

| Group | Estimated new statements | Scope |
|---|---|---|
| B. dbhandler error paths | 120 to 150 | begin, commit, query, exec, scan, rows.Err (injected with `RowError`; the separate `Close()` return branch of `ContactList` cannot be reached with sqlmock and is not targeted), rows-affected, deadlock (1213) and duplicate (1062) failures of the address, ownership, contact, case note, tag assignment and scan helpers |
| C. listenhandler | 20 to 35 (any shortfall is made up in B and A) | bad URI, bad body, missing field and handler error to status code mapping in the v1 case, contact, contact address and interaction handlers, two routing branches, the URI helpers (`caseIDFromURI`, `caseSubIDFromURI`) and `errorResponse` (its `ToResponse` failure branch and the consume-goroutine log branch of `Run` are not targeted). Status codes alone do not tell which validation branch ran, so each case uses a strict gomock with no handler call expected and the target blocks are confirmed in the coverage profile. Branches that only fire when `json.Marshal` of a domain value fails are not targeted |
| D. handlers | 25 to 35 (any shortfall is made up in B and A) | `contacthandler` not-found and error propagation, address type check, `casehandler` error propagation, `NewCaseHandler`, `addresshandler` delegation and constructor, `CreateWebhookEvent` error |
| A. cmd (top-up) | 0 to 60 | behavior only: wrapped error texts of the `initHandler` failure and the `runCreate` argument validation, `resolveUUID` and `printJSON` results, `resolveUUID` messages for missing and malformed ids (the commands do not use cobra required flags), `runListen` and `runSubscribe` error handling, `contact-control` command trees with flag defaults and the `resolveUUID` required and malformed id messages; `case-control` adds few statements and gets one concrete flag-binding assertion |

Group B method: query-builder failure branches are not targeted; pick targets from the uncovered block list of the baseline profile (not from function names), reuse the existing harness (`newCtxRowsHandler`, the sqlmock setups of `address_deadlock_budget_test.go` and `ownership_helpers_test.go`), and add no duplicate helper. Sqlmock expectations are ordered and closed with `ExpectationsWereMet`. Each scenario is one injected failure checked with `errors.Is` or the wrapped function text, and a returned nil value.

Group A details:
- `initHandler` with a malformed DSN fails inside `sql.Open` without a network; a well formed or empty DSN would reach the ping and dial the default local port, so it is never allowed. Every test that can reach `initHandler` sets a valid UUID through viper first (`runCreate` validates it before `initHandler`; the other `run*` call `initHandler` first) and calls `runCreate`, `runGet` and the other `run*` functions directly (not through `Execute()`, whose `PersistentPreRunE` runs the once-only `config.LoadGlobalConfig` and could overwrite the injected value) after a shared helper has set `config.Get().DatabaseDSN` to a malformed value and registered its restore; a new `TestMain` in the `cmd/contact-control` test package (the `cmd` packages have no test files today) consumes `LoadGlobalConfig()` once before any test and then sets `DatabaseDSN` to a malformed value as a second guard (individual tests restore it in `t.Cleanup`). The `cmd/contact-manager` tests send no signals, because its `init()` already starts the one-shot signal goroutine. The tests assert the wrapped text, and one test asserts that the failure text is the malformed-DSN open error, not a ping error; a manual `ss` check of the default local database port while the new `cmd` tests run alone with `-run` is recorded as extra evidence.
- `runListen`: the test asserts that the return value is nil and no consume call follows a failed `QueueCreate`, plus the success path with the bounded wait below. `runSubscribe` returns the error: asserted with `errors.Is` for each injected failure (`QueueCreate`, `TopicCreateWithKind`, `QueueBind`).
- Mock goroutine waits use `select` with `time.After` as an upper bound and `DoAndReturn` with the exact argument list; a failing mock must not leave a `WaitGroup` waiting.
- `config.LoadGlobalConfig` runs once per process and `viper.Reset()` does not re-arm it. Tests therefore never assert values loaded through it. `PersistentPreRunE` is only checked to return nil and bind flags, `config.Get().DatabaseDSN` is assigned and restored by tests that need it, environment variables are isolated with `t.Setenv`, and the command is rebuilt per test.
- `printJSON` writes to `os.Stdout`; the test swaps it with a pipe and restores it in `t.Cleanup`.
- `signalHandler`, `run`, `runService`, `initProm` and everything after a successful `initHandler` are not tested.

Other harness rules: the sqlite database is shared with one connection and the existing dbhandler tests insert fixed ids, so new tests do not add sqlite-based cases and use sqlmock only. Tests that touch `viper`, `config` or `os.Stdout` do not use `t.Parallel()`, and every `viper.Set` is undone in `t.Cleanup` (key restore or `viper.Reset()`). Values are synthetic (reserved phone range `+1555...`, `example.com`, generated UUIDs); no network, no external cost.

## 3. Verify

- Target blocks: after each group, the baseline uncovered block list is compared with the new profile to confirm that the intended blocks were covered and the group meets its estimate.
- Floor: hand-written total at least 80.0%; recommended 80.5%; target 81%. Measured with `GOFLAGS=-mod=mod go test -count=1 -coverprofile` and the baseline filter (exclude `/gens/`, `mock_*.go`, `DO NOT EDIT` header files; merge duplicate blocks by maximum count). The PR body gives the command, the filter, the per-package before and after table and the raw total next to the hand-written total.
- New tests pass with `-race`, `-shuffle=on` and `-count=2`, run on the new test names (`-run`) in every touched package. Whole-package runs under `-shuffle=on` or `-count=2` are also tried; a package whose existing tests already fail the same way on the unchanged baseline (observed at design time: `pkg/dbhandler` under shuffle and on a second run, `pkg/casehandler` and `internal/config` on a second run) is reported in the PR body with the baseline evidence instead of being changed. New `pkg/dbhandler` and `pkg/casehandler` tests do not use the shared sqlite database (`dbTest`): the first uses sqlmock and the second uses `dbhandler.MockDBHandler` (with a sqlmock transaction where one is needed); existing tests pass; `golangci-lint run` is clean; `bash scripts/check-test-conventions.sh` passes (`Test_` names, `reflect.DeepEqual` with `t.Errorf`, gomock controller named `mc`); `git diff origin/main...HEAD --stat` is limited to bin-contact-manager test files and this document; no go.mod or go.sum change after `go mod tidy`.
- `bash scripts/check-test-conventions.sh` is run after the tests are added and after `git fetch origin main` (it needs `origin/main` as a local ref; on the unchanged baseline it checks nothing).
- Assertion standard: error tests check the injected error or sentinel with `errors.Is` or the exact wrapped text and a nil returned value; sqlmock tests call `ExpectationsWereMet`; CLI tests assert error texts and results, not just that a command exists. Call counts alone, empty calls and self-comparison are not accepted.
- Mutation sample, run in a scratch copy and recorded in the PR; the intended new test must fail for each mutation, failures of other new tests are recorded, and everything passes again after the mutation is reverted. Before the run, each mutation is checked to be a location the existing tests do not already cover: B (drop the deadlock mapping of one `*Tx` helper, drop one `rows.Err()` check), C (change one 400 status to 500 in a validation branch), D (drop one error propagation in `casehandler`), A (change the wrapped text of the `initHandler` failure; drop the `Run` call in `runListen`).
- Public repository hygiene on `git diff`, PR body and test comments: no real hosts, addresses, secrets or personal data, and no wording that points at a defect location or condition.
