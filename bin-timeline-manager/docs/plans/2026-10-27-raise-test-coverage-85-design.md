## 3. Plan (new test files only, no product code change)

Conventions: new tests are named `Test_<Func>_<scenario>` (existing `TestXxx_NoConnection` tests stay as they are, so both styles coexist in a file), table style where it fits, no testify, synthetic values only. New tests are placed in new files instead of the existing test files, to leave them untouched: correlation_query_test.go, event_query_test.go, event_insert_test.go, peer_event_insert_batch_test.go, peer_event_query_test.go, main_test.go (WaitForConnection) in pkg/dbhandler, and cmd/timeline-control/migrate_test.go. The plan items below name the behavior, and the file mapping is this list. Doubles live in pkg/dbhandler/helper_test.go (a helper file with no source counterpart and no unused fields, because the unused linter applies to tests; the convention gate checks only Test_ prefixes, testify and the `mc` name).

Fake design: `fakeConn` embeds clickhouse.Conn and overrides only Query and PrepareBatch; it records the ctx, query text and args. `Query` returns an untyped nil Rows together with an error (never a typed-nil pointer, which would panic in `defer rows.Close()`). `fakeRows` embeds driver.Rows and overrides Next, Scan, Err and Close; it counts Close calls, supports an error that appears only after a given number of Next calls, and an explicit `scanErr` injected on a chosen row. Scan assigns by destination type (`*string`, `*time.Time`, `*[]string`) and calls t.Fatalf on any other type or a destination count mismatch. `fakeBatch` embeds driver.Batch and overrides Append, Send; it records the Append argument lists, counts Send calls and can fail Append or Send on a chosen call. Every column in fixtures carries a distinct value (publisher, event type, data type, direction and so on) so that swapped Scan or Append positions are visible.

Assertions on errors check the wrapping phrase through `err.Error()` (query, scan and Err paths each have their own phrase, but `error iterating rows` is shared by six functions and `could not scan event row` by two, so each path is asserted separately) and the cause through errors.Is, because Wrap alone keeps errors.Is true. Sentinel errors injected by the tests never contain these phrases. SQL text is compared after whitespace normalization (strings.Fields joined by one space) and args are compared as literal slices in order; the normalized SQL is not copied from the builder output. `fakeRows.Err` returns its error only after Next has returned false. Every Query path asserts `closed == 1` on success and on every error after the rows were obtained.

1. correlation_test.go: ResourceActiveflowIDGet: nil conn; query error; no row with Err nil returns "" and nil; no row with Err set; scan error; success returns the id with the literal query text and args. ResourceExists: nil conn; query error; no row; no row with Err; row returns true. CorrelatedResourceList: nil conn; query error; scan error on the second of two rows returns nil result; Err set after one Next; empty result is a non-nil empty slice; two rows mapped field by field; literal args in the order (activeflow id, limit). The ctx received by Query is not the parent ctx itself (a derived context carries the settings) and is cancelled when the parent is cancelled (asserted once, in the first Query test; the max_execution_time values 5 and 10 are not readable through a public accessor, so mutations of those constants are not detected).

3. event_insert_test.go (new file): EventBatchInsert cases: nil conn returns `clickhouse connection not established` (no existing test covers it); empty rows with a connection is a no-op (PrepareBatch call count 0); PrepareBatch error (Send 0); Append error on the first row (Send 0); Append error on the second row (Send 0); Send error (Send exactly 1); a one-row batch; success: the PrepareBatch SQL compared after whitespace normalization, the exact five values per row in column order with distinct values, Send exactly 1.
