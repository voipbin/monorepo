## 3. Plan (new test files only)

Conventions (constructor tests are the exception to the direct struct construction rule, the other tests build the handler structs directly): names `Test_<Func>` or `Test_<Func>_<scenario>`, table style where it fits, `mc := gomock.NewController(t)` with `defer mc.Finish()`, no testify, synthetic values only (documentation IP ranges, `test-` prefixed tokens), expected values are literals and never derived from the code under test. No sleeps, no real network except loopback httptest servers, global state (viper config, environment, signal channels) is restored with t.Cleanup and the tests that touch it do not use t.Parallel. Existing test files are not edited; new tests go to new files. Fixtures use fixed UUID literals and failures are reported with the `Wrong match. expect: ..., got: ...` form (the service test conventions). The metrics endpoint start-up with a configured endpoint is not exercised (it registers on the process-wide default mux and opens a listener). Goroutine-based start-up tests wait on a channel with a bounded `select` (a hung wait must fail the test, not stall it), mocks used inside goroutines are declared with the exact signature of the mocked method (variadic arguments included), and a log line written inside a goroutine is used as a signal only where that log line is the behavior under test (the consume failure), followed by the done channel for the end of the test.

1. pkg/siphandler/gcsreader_impl_test.go: loopback fake of the GCS JSON API plus object download. ListObjects: names returned in server order, prefix forwarded as the query value, empty result is a non-nil empty slice, a listing failure uses a non-retried client status such as 403 (a 5xx makes the client library retry for minutes) and returns a wrapped error that names the prefix and keeps errors.Is for the cause. DownloadObject: bytes written to the destination equal the object body, missing object returns the open error naming the object, destination writer that fails returns the download error, truncated body (declared length larger than sent) returns the download error within a bounded time (the client library retries once, the test asserts the error and runs under a context timeout). The fake routes the listing path and the object download path separately, and for the truncated case it answers the retry (a range request) with a short body again so the retry cannot succeed. NewGCSReader returns a reader bound to the given bucket (asserted through a request path).
2. pkg/siphandler/rtp_extra_test.go: fetchRTPPcaps truncates a listing above the file cap (21 objects against a cap of 20) and downloads exactly the cap (mock GCSReader, exact object names), temp file creation failure (TMPDIR pointing to a missing directory) skips every object and still returns a no-op cleanup; GetPcap where the SIP message lookup fails returns the merged data untouched, and GetPcap with a SIP message carrying an SDP endpoint rewrites the RTP packet address (success path, literal bytes compared); mergeMultiplePcaps with no sources and with only unreadable sources returns an empty non-nil slice, and with several packets per source interleaves them by timestamp (all timestamps distinct so the order is not decided by input order); filterInternalPackets on invalid pcap bytes returns an error; GetPcap with an invalid RTCP pcap falls back to the SIP data; a download mock that closes the destination file makes the seek step fail and that object is skipped; rewriteRTPPacketIPs on invalid pcap bytes returns an error; rewritePacketIPs leaves the packet unchanged for non-IPv4, non-UDP and an unsupported link type, and honors the VLAN offset, the raw link type and a decodable non-Ethernet link type such as null (crafted packets whose expected bytes are built independently of the implementation: the IP header checksum is recomputed and the UDP checksum is zero in the expected value; every object of the cap is expected exactly once and the returned order is checked through file contents); the SDP body extraction without a separator; a destination-only port match.
3. cmd/timeline-manager/helpers_test.go: runMigrations with an empty address returns nil without touching the network; with a privileged loopback port that nothing listens on returns the wrapped init error (the migrations path is an existing temporary directory, so the case does not depend on the working directory). The config is changed through the fields of `config.Get()` (the config is a process-wide singleton loaded once) and restored in cleanup. initSignal: a signal value sent on the package channel arrives as a done notification (the done and signal channels are drained at the start of the test and again in cleanup, and signal.Stop is called in cleanup, so a value left by an earlier test cannot satisfy the assertion). initProm: disabled when the endpoint or the listen address is empty, asserted by checking that no handler was registered on the default mux for the endpoint (an empty endpoint with a set listen address and the reverse are separate cases). runListen: queue creation failure is logged and nil returned (the test asserts the observed result), success starts the consumer (mock socket handler, synchronization by channel, no sleeps). runSubscribe: queue creation failure returns the error and a nil channel; runDaemon with a closed loopback address returns the migration error after signal and metrics initialization (no service connection is made); the closed address is a low loopback port on which nothing listens.
4. cmd/timeline-control/commands_test.go: Execute through the command tree: `event list` with only the publisher flag must fail with the missing id error (the value is read through the viper binding made by the pre-run hook, so removing the hook changes the error); the migrate init failures are already covered by existing tests and are not repeated; `migrate-mysql status` with a DSN value that fails at the parsing step (no slash, so no network access and no dependence on a local database; an empty DSN is not used because it normalizes to the default address) covers the MySQL recovery command closure, asserted on the migrator initialization error prefix and the parsing cause. the global config is loaded once explicitly by the test helper before its fields are set, and the related environment variables (id, events, publisher and the connection settings) are cleared with t.Setenv; viper is reset before the command tree is built and in cleanup (a reset after the build removes the flag bindings) and cobra output is redirected to buffers, because the hook binds flags into the global instance and earlier tests leave overrides behind; the arguments are set explicitly on the root command, and config fields are set after the first Execute because the config is loaded once from the environment on first use; printJSON with an unmarshalable value returns the wrapped error. The runEventList validation cases already exist and are not repeated.
5. pkg/listenhandler: a mocked handler that returns a value that cannot be encoded makes the response encoding fail, which is the only way a route returns an error; this drives the default error handling of processRequest (nil error, status 400, empty data, and the error log message asserted through a logrus test hook removed in cleanup) through the events and aggregated events routes (invalid raw JSON field) and the correlations route (a time value outside the encodable year range), and the 500 response of the analysis response helper called directly (invalid raw JSON result); the logrus hooks of the listen and subscribe tests are non-blocking so a late log line from a leftover goroutine cannot block; the correlations handler with a too short URI is called directly.
6. Constructors of pkg/analysishandler and pkg/analysisdbhandler return the concrete handler with the injected dependencies in place (compared by identity against the injected mocks and values, the semaphore capacity, and the identity of the metric fields). pkg/homerhandler: response body read failure (declared length larger than sent) for the three request methods, each asserted on its own message and on errors.Is with the unexpected EOF cause. pkg/analysishandler: enrichment when the reference cannot be resolved (all blocks empty), chased origin that cannot be resolved (header only plus marker), final-status mapping for the conversation status whose branch is not yet covered; the start paths that launch the background analysis job are not targeted (the job runs on its own goroutine and the existing tests avoid it on purpose because of races with the mocks). pkg/subscribehandler: Run with queue creation failure returns the error, a consumer failure is logged with the mock error text (asserted through a logrus test hook that signals a buffered channel without blocking from inside the log call, filtered by message because earlier goroutines may log too; the test cancels the context and waits for the done channel so no flush worker leaks); a failing peer event batch insert is logged with its error (same hook, inline fixtures) and the flush still completes (mock database handler).

The analysishandler enrichment and final-status cases of item 6 were left out because the target was already met by the other groups.

Added after measurement if the total is below 90.5%: further branches of the same packages found in the profile. The order of work is 1, 2, 3, 4, then the rest, with a measurement after each group.
