# bin-conversation-manager 단위 테스트 커버리지 85% 상향 (VOIP-1659)

## 1. 이슈 분석 (착수 전 티켓 검토 결과)
- 측정 대상 커밋: origin/main a47f5a2a1394 (카드 기준 커밋 320acbfc2 와 이 서비스 디렉터리에 차이가 없다). 작업 브랜치는 이 커밋 위에서 시작한다.
- 측정: `GOFLAGS=-mod=mod go test -count=1 -coverprofile=cp.out ./...` 후 수기 집계(gens/, mock_*.go, `Code generated ... DO NOT EDIT` 파일 제외, 같은 블록은 최대 count). `-coverpkg` 는 쓰지 않는다.
- 기준선(수기): 2991/3719 = 80.42%, 테스트 실패 0건. 카드의 80.40%/3719(320acbfc2 기준)와 소수점 차이만 있다. 85.0% 까지 171, 85.5% 까지 189 statement 가 더 필요하다.
- 패키지별 미커버(statement): cmd/conversation-control 217, cmd/conversation-manager 178, pkg/dbhandler 102, internal/logtest 75, pkg/linehandler 53, pkg/listenhandler 40, pkg/whatsapphandler 18, pkg/conversationhandler 10, pkg/subscribehandler 8, pkg/messagehandler 7, internal/config 5, pkg/accounthandler 5, pkg/smshandler 3, internal/convtitle 2, models 4, pkg/cachehandler 1.
- 도달 가능 상한: 아래 3절 제외를 적용하고 4절의 항목을 모두 달성하면 약 280 statement 가 늘어 약 88% 이다(독립 실측과 소스 분류로 보수 약 280, 느슨하게 약 305). 필요량(189) 대비 약 90 statement 의 여유가 있어 block 사유(상한 85% 미만)에 해당하지 않는다. 선행 PR(VOIP-1647, 1649, 1652, 1657)이 이미 올린 항목(cachehandler, conversationhandler, listenhandler 대부분)은 반복하지 않는다.
- VOIP-1416(80% 미만 패키지 일반 상향) 중복: 이 서비스에서 수기 80% 미만인 패키지는 cmd/conversation-control(58.9%), cmd/conversation-manager(12.3%), internal/logtest(0%), pkg/linehandler(73.8%) 네 곳이며 PR 본문에 명시만 하고 흡수 여부는 따로 판단하지 않는다.

## 2. 목표
- 수기 합계 85.5% 이상(최소 85.0%). 필요 증가량 189 statement, 계획 합계는 약 280.
- 집계 지표 주의: 이 지표는 같은 단위가 여러 range 로 나뉜 블록의 statement 수를 range 마다 합산하므로 실제 statement 수가 아니라 이 지표의 가중치다(예: manager 의 runMain 앞부분 한 구간이 40 이상으로 잡힌다). 목표는 이 지표로 판정한다.
- 요건: 비테스트 .go 변경 없음, 외부 연결과 시간과 네트워크에 의존하지 않음, 합성값만 사용, 자기비교식 테스트 금지.

## 3. 제외(도달 불가 또는 외부 연결 필요)
- 각 main 의 `main()`, manager 의 `run()` 내부 RabbitMQ 연결, `initProm` 의 서버 고루틴 재시도 루프, `initHandlers` 의 DB 연결 이후 구간, run* 의 핸들러 호출 이후 구간.
- json.Marshal 실패 응답 분기(listenhandler 의 500 응답 약 20, listenhandler 의 errorResponse 가 ToResponse 실패를 처리하는 분기 포함), dbhandler 의 PrepareFields 와 squirrel ToSql 와 ApplyFields 오류 반환과 RowsAffected 오류, 설정 바인딩 오류와 Fatalf, `models` 의 json.Marshal 오류 반환.
- linehandler 의 LINE 클라이언트 외부 호출(Send 의 PushMessage, Setup, Teardown 의 Do, GetPeer 의 프로필 조회). getClient 실패 경로는 대상이다.

## 4. 패키지별 계획과 verify
새 테스트 파일을 추가하고(제품 파일과 이름이 겹치지 않도록 `*_coverage_test.go` 로 둔다) 기존 테스트 파일은 고치지 않는다. 규약: 함수 이름은 `Test_<대상>`, gomock 컨트롤러 변수는 `mc`, 표 기반, 외부 네트워크와 sleep 없음, 합성 값만 사용(비밀번호 리터럴은 별도 대입).
1. cmd/conversation-control (약 33): 잘못된 DSN(run* 은 `config.Get().DatabaseDSN` 을 직접 읽고 `config.Get()` 이 전역 포인터를 돌려주므로 테스트가 DatabaseDSN 을 직접 지정한다. 모든 케이스에서 DSN 을 명시하고 빈 값을 쓰지 않는다(빈 DSN 은 드라이버 기본 주소로 가므로). 기존 `resetState` 를 재사용해 설정과 viper 를 복원한다. 거부 주소는 자격 증명이 없는 `tcp(127.0.0.1:1)/db` 형태로 쓴다. 괄호 없는 `127.0.0.1:1` 은 DSN 파싱 오류가 되어 연결 거부 경로에 닿지 않는다)으로 run* 10개가 "failed to initialize handlers" 로 감싼 오류를 반환하는지 표 기반으로 확인한다. initHandlers 의 DB 연결 실패 래핑. verify: 오류 메시지 접두와 원인 보존(errors.Unwrap), 필수 입력이 없는 run* 도 DB 연결 실패가 먼저 반환됨을 확인한다(순서 고정). 파일: cmd/conversation-control/run_coverage_test.go.
2. cmd/conversation-manager (약 52): runMain 이 잘못된 DSN 에서 오류를 반환하고 종료하지 않음. 설정은 환경변수 `DATABASE_DSN`(`tcp(127.0.0.1:1)/db` 형태)과 `PROMETHEUS_LISTEN_ADDRESS`(`127.0.0.1:0`)를 `t.Setenv` 로 첫 runMain 호출 전에 주입한다(runMain 안의 `config.Init` 이 once 로 환경값을 읽어 전역을 덮어쓰므로 전역 직접 대입은 쓰지 않는다. 대입하면 로컬 3306 과 2112 포트를 건드릴 수 있다). runMain 호출 전에 `config.Init` 이나 `LoadGlobalConfig` 가 이미 호출되어 once 가 소진되지 않았는지(DSN 이 기대값인지) 확인하는 가드를 둔다(첫 반복은 빈 값, 이후 반복은 기대값 둘 다 허용하고 그 밖의 값이면 실패). runMain 은 전역 상태를 바꾸므로(`http.DefaultServeMux` 의 /metrics 등록은 두 번째 호출에서 panic, initSignal 은 호출마다 signalHandler 고루틴을 추가, rootCmd 의 args 와 viper 와 config 전역) 테스트가 `http.DefaultServeMux` 를 새 mux 로 교체하고 `signal.Reset` 과 rootCmd 인자를 정리해 `-count` 반복에 안전하게 한다. 전역 설정과 viper 는 복원하지 않는다(config 의 once 가 비공개라 리셋할 수 없고, 비운 뒤의 반복은 DSN 이 빈 값이 된다. `viper.Reset` 도 금지: init 에서 만든 플래그 바인딩이 사라진다), initSignal 후 chSigs 신호가 chDone 으로 전달되는 signalHandler(타임아웃이 있는 select 로 대기, sleep 없음), 기존 runListen 과 runSubscribe 의 보완. verify: 반환 오류가 `127.0.0.1:1` 주소의 연결 거부를 담고 있음(3306 이 아님), chDone 수신. 신호 테스트는 시작 전에 chDone 을 비우고(이전 호출이 남긴 signalHandler 고루틴 경쟁 방지) 타임아웃이 있는 select 를 쓴다. 파일: cmd/conversation-manager/runmain_coverage_test.go.
3. internal/logtest (약 74): Capture 가 레벨과 출력과 훅을 복원, variants 4형태, containsSentinel, AssertNoLeak 의 정상(무누출) 경로와 누출 감지(평문, base64, 십진 목록, URL 인코딩, 금지 타입 필드 중 `sock.Request` 와 `account.Account` 계열만 쓴다. `request.V1DataHooksPost` 는 `pkg/listenhandler/models/request` 를 listenhandler 밖에서 참조할 수 없는 계층 규칙 때문에 쓰지 않으며 손실은 미미하다)와 빈 항목 거부. 실패 경로는 `&testing.T{}`(zero value)를 AssertNoLeak 에 넘겨 `Failed()` 로 검증한다(Go 1.27 에서 동작 확인, Capture 는 정상 `t` 로 호출). verify: 누출 입력은 실패를 기록하고 무누출 입력은 기록하지 않는다. 파일: internal/logtest/logtest_coverage_test.go. 전역 logrus 상태를 쓰므로 병렬 실행하지 않는다.
4. pkg/dbhandler (약 40): 테스트 전용으로 `sql.Open("sqlite3", ":memory:")` 한 뒤 Close 한 별도 DB(기존 TestMain 의 공유 인메모리 DB 는 닫지 않는다)와 오류를 돌려주는 gomock 캐시로 Create, GetFromDB, List(AccountList, ConversationList, MessageList), MessageGetsByTransactionID, Update, Delete, ConversationGetBySelfAndPeer 의 실행 오류 경로, rows affected 0 의 ErrNotFound(닫은 DB 가 아니라 열린 공유 인메모리 DB 에 없는 id 로 AccountDelete, MessageUpdate, MessageDelete 를 호출해 도달), List 의 빈 토큰 처리, 행 스캔 오류, 캐시 Set/Get/Update 실패 분기(account, conversation, media, message 각각). 외부 상태는 케이스마다 새 DB. verify: 반환 오류 문구와 `sql: database is closed` 원인 보존, ErrNotFound 일치, 정상 경로에서 캐시 갱신 호출 인자. 파일: pkg/dbhandler/closed_db_coverage_test.go (기존 `error_paths_test.go` 같은 파일과 이름이 겹치지 않는지 push 전 확인).
5. pkg/linehandler (약 21): hookEventHandle 의 빈 이벤트와 nil 반환, getClient 의 계정 검증 실패(`linebot.New` 가 secret 이나 token 이 비면 오류)로 Send, Setup, Teardown, GetPeer 의 getClient 실패 경로, follow 이벤트의 GetPeer 오류 전파. 프로필 조회, PushMessage, Do 이후는 외부 호출이라 제외한다. verify: 반환 오류에 원인 보존, 요청 핸들러 mock 이 호출되지 않음. 파일: pkg/linehandler/client_coverage_test.go.
6. pkg/listenhandler (약 16): NewListenHandler 와 Run(gomock sockhandler 의 QueueCreate 성공과 실패, ConsumeRPC 호출과 큐 이름 인자 단언), processRequest 의 오류 응답 두 분기, hooks 의 남은 분기. 파일: pkg/listenhandler/run_coverage_test.go. `Run` 의 ConsumeRPC 는 고루틴에서 호출되므로 `DoAndReturn` 안에서 채널을 닫고 타임아웃 select 로 기다린 뒤에 mc.Finish 가 실행되게 한다(sleep 금지).
7. 그 밖 (약 45): whatsapphandler 는 provider_data 오류, 서명 접두 오류, 서명이 맞는 깨진 JSON, Hook 의 중복 확인과 대화 조회 생성 갱신과 메시지 생성 오류, Send 의 HTTP 오류와 응답 형식 오류(httptest 로컬 서버), Teardown. subscribehandler 는 Run 의 큐 생성과 토픽 생성과 바인딩 실패, processEventRun(`go h.processEvent(m)` 이므로 핸들러 mock 의 호출 신호를 채널로 받아 타임아웃 select 로 기다린다), ConsumeMessage 오류 로그(고루틴은 `DoAndReturn` 안에서 채널을 닫고 타임아웃 select 로 기다리는 기존 `Test_runListen` 패턴). messagehandler 와 accounthandler 의 미커버 분기와 생성자(조회 실패는 반환 오류에 원인 보존, 생성자는 non-nil 과 주입 의존성 확인), smshandler 전송 오류(요청 핸들러 오류가 그대로 반환됨), convtitle 의 webchat 제목과 라벨이 없는 타입의 폴백(리터럴 기대값). whatsapphandler Send 테스트는 전역 `GraphAPIBase` 를 defer 로 원복하고 병렬 실행하지 않는다. listenhandler 의 processRequest 오류 분기는 핸들러가 오류를 상위로 반환하는 경로(account 생성 오류)로 유도한다. conversationhandler 는 도달 가능한 것만(outbound 성공 반환, 다중 target 경고, 생성자). `runExecuteModeAgent` 가 항상 nil 이고 `getExecuteMode` 가 두 값만 반환하므로 agent 오류와 default 분기는 대상이 아니다.

## 5. 검증
- 새 테스트 함수 이름이 같은 패키지의 기존 테스트 함수 이름과 겹치지 않는지 push 전에 확인한다(예: subscribehandler 의 `Test_Run_BindsTopicExchangeBeforeConsuming`, `Test_NewSubscribeHandler`, listenhandler 의 `Test_processV1HooksGet` 계열).
- 항목별 기대 증가량 합계(독립 탐침 실측 포함): control 33, manager 52, logtest 74, dbhandler 40, linehandler 21, listenhandler 16, 그 밖 45 = 약 281. 필요량 189 대비 약 90 의 여유가 있다.
- `go mod tidy`, `go mod vendor`, `go generate ./...`, `go test ./...`, `golangci-lint run -v --timeout 5m`, `scripts/check-test-conventions.sh`, 반복 실행(`-race -count`)으로 순서 의존과 시간 의존이 없음을 확인한다. go.mod 와 go.sum 은 바뀌지 않는다(miniredis 는 필요 없음).
- 수기 합계가 85.5% 이상임을 위 측정 방법으로 확인하고 패키지별 전후 표를 PR 본문에 쓴다.
- 변이 표본(제품 코드를 임시로 바꿔 새 테스트가 실패하는지 확인한 뒤 되돌림): run* 오류 래핑 문구, signalHandler 의 chDone 전송, logtest 의 base64 변형, dbhandler 의 rows affected 0 처리, listenhandler 의 400 응답, whatsapphandler 의 서명 접두 검사, linehandler 의 빈 이벤트 거부, subscribehandler.Run 의 큐 생성 실패 반환 문구(토픽 생성과 바인딩 실패는 각각 별도 케이스로 단언), dbhandler 의 `rowsAffected == 0` 반환을 nil 로 바꿈.
- PR 본문에 쓸 것: 패키지별 전후 표, 수기 합계와 원본(`go tool cover -func` 의 total) 합계, 제외 방법(gens/, mock_*.go, `Code generated ... DO NOT EDIT` 파일 제외와 같은 블록은 최대 count), 측정 명령과 플래그(`GOFLAGS=-mod=mod go test -count=1 -coverprofile=cp.out ./...`, `-coverpkg` 미사용), VOIP-1416 과 겹치는 패키지 명시(흡수하지 않음).
- push 전 확인: `git diff --stat origin/main...HEAD` 의 파일이 모두 `bin-conversation-manager/` 안이고 변경 파일이 모두 새 `*_test.go` 와 이 설계 문서이며(비테스트 .go 와 기존 테스트 파일 변경 없음), `go mod tidy` 와 `go mod vendor` 뒤 `git diff --stat` 로 go.mod 와 go.sum 이 바뀌지 않았고, 커밋 작성자가 저장소 관리자 설정값이다.
- 롤백: PR 되돌림으로 충분하다(테스트만 변경).
